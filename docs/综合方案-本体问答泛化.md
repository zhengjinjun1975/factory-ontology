# 综合方案：本体问答泛化（9行业共性根因 + 两阶段建模 + schema linking）

> 目的：不再"有问题就解决"的零散修补，而是基于 9 大行业横向比较的共性根因，结合全网调研的成熟方案（schema linking / data profiling / BYOKG），给出相对泛化的综合性方案。

---

## 一、9 行业验证结果与共性根因

**9 组行业数据**（全部生成+建模+验证）：阀门/机械/食品/化工/地震/精加工/波纹管/环保/造船

**漏掉问题横向比较，收敛为 4 类共性根因（非零散 bug）：**

| 类 | 根因 | 表现（漏答） |
|----|------|------------|
| A | 实体总数映射硬编码 {设备:equipment,...} | 测线/炮点/项目/船坞/船 计数不命中 |
| B | 极值字段映射不全 | 精度/投资/价格/吨位/金额 极值不命中 |
| C | 类型计数映射不全 | 大气治理/脱硫/油轮 类型计数不命中 |
| D | 材质/属性值同义词覆盖不全 | 不锈钢波纹管 材质计数不命中 |

**本质**：规则引擎的查询映射是**硬编码**的（实体名/字段/类型），换行业即不命中。

---

## 二、全网调研结论（别人怎么解决）

成熟方案指向同一方向：**不再硬编码，让 schema linking + data profiling 自动生成映射**。

1. **Schema Linking**（最成熟）：Text-to-SQL 把"问题里的实体/字段 mention → schema 元素"自动链接（X-SQL/AttnLink/RASL），零硬编码，新行业喂 schema 即用
2. **Data Profiling 自动词典**：建库时对每列做类型探测 + 枚举 distinct 值，丢给 LLM 生成该行业 `中文→标准值` 同义词表（Elasticsearch LLM 同义词方案）
3. **Schema-Guided 逻辑形式生成**（SG-KBQA/BYOKG）：给定 schema 上下文，LLM 自动产出 COUNT/ARGMAX 等结构化查询，无需预定义可极值字段
4. **BYOKG**（零样本/免标注/任意 KG）：KG 探索 + 程序合成，换 schema 即用（GrailQA 零样本 +27.89 F1）

---

## 三、综合方案：两阶段建模（结合你的方向）

### 阶段一：规则 + 大模型 自动本体建模/词典（粗粒度，覆盖 90%+）
在现有 `suggest_schema` + `_build_lexicon` 基础上，增加 **data profiling 自动生成全部查询映射**：
1. **实体总数映射自动生成**（解决 A）：从 suggest_schema 的表名 + 中文 label 自动生成 {中文实体名: 表名} → 测线/炮点/项目/船坞/船 自动可计数
2. **极值字段自动识别**（解决 B）：data profiling 识别数值列（精度/投资/价格/吨位/金额），自动纳入极值模板 → 极值查询自动命中
3. **类型枚举自动收集**（解决 C）：枚举列 distinct 值自动进 type_cn2en（已有，补全到所有枚举列含产品类型/项目类型）→ 大气治理/油轮 自动可计数
4. **属性值同义词自动生成**（解决 D）：材质/枚举 distinct 值 + LLM 生成同义词（已有 synonym_map，补全到所有属性值列）

### 阶段二：精细化人工辅助（解决剩余长尾，覆盖到 98%+）
提供**人工辅助界面**，让用户微调/补充映射：
1. **映射审查界面**：展示自动生成的实体/字段/类型/同义词映射，用户可增删改
2. **词典编辑器**：手动补充未识别同义词/字段别名
3. **失败反馈闭环**：用户问一个"未定位"的问题，系统提示"是否要补充映射？"，用户确认后入该行业词典

### 兜底：schema linking 运行时动态映射
- 对规则未命中的查询，用 **schema linking**（把问题 + 当前行业 schema 元素给 LLM）动态产出映射，替代硬编码兜底

## 四、实施优先级（按性价比）

| 优先级 | 改进 | 解决 | 依据 |
|--------|------|------|------|
| **高** | 建库 data profiling 自动生成实体/极值/类型/同义词映射 | A/B/C/D | Elasticsearch LLM同义词; NL2SQL profiling |
| **高** | 人工辅助映射审查界面 + 词典编辑器 | 剩余长尾 | 两阶段范式 |
| **中** | 运行时 schema linking 兜底 | 规则未命中 | X-SQL/AttnLink |
| **远期** | BYOKG 零样本探索 | 完全免人工 | BYOKG |

> 一句话：**把"硬编码映射"改为"建库时 data profiling 自动生成 + 人工辅助精细化 + 运行时 schema linking 兜底"**，实现跨行业换数据即用的真正泛化。

## 五、预期效果

- 阶段一自动生成后：9 行业命中率从当前的 61-100% 不均 → **统一提升到 95%+**
- 阶段二人工辅助后：长尾问题可补齐到 98%+
- 换任何新行业：只需建库（自动生成映射），少量人工微调即可达到高命中

## 六、混合检索：语义向量 + BM25 + 图谱（提升模糊查询命中率）

> 用户方向：检索采用语义、向量等技术手段混合检索，提升命中率。
> 可行性已验证：本地 Ollama `nomic-embed-text`（768维），"最贵的产品"vs"价格最高的产品"相似度 0.749、"油轮"vs"船舶类型" 0.954——语义检索能识别同义/语义相近。

### 当前检索链路（缺向量）
规则引擎(确定性) → GraphRAG(BFS子图+查询改写+LLM) → BM25(稀疏) → miss
**缺**：语义向量检索（embedding），无法处理语义模糊/同义/口语化查询。

### 混合检索方案（语义 + 稀疏 + 图谱 融合）
```
查询 → ①规则引擎(确定性命中) ②GraphRAG图谱 ③BM25稀疏 ④向量语义检索(embedding) → 融合排序 → LLM生成
```
- **向量语义检索**：建库时对实体/属性值做 embedding（本地 nomic-embed-text），查询时向量召回语义相近实体，解决"最贵/油轮/语义同义"类模糊查询
- **混合融合**：BM25(稀疏) + 向量(语义) 分数加权融合，召回更全
- **零额外成本**：用本地 embedding 模型，无 API 依赖

### 实施
1. 建库时对实体名/属性值生成向量索引（nomic-embed-text）
2. 查询时向量检索召回 top-k 语义相近实体
3. 与 BM25 分数融合，喂给 LLM/规则
4. 本地优先，embedding 失败回落（不阻塞）
