# 本体检查 (ontology_check)

工厂本体库的 **本体检查** 能力：核查全库的 **数据质量 / 链路断链 / 一致性**，
输出 **0-100 综合得分** + **分类子分** + **问题清单**，并给出通过/失败判定。

独立 CLI、纯 Python 标准库（零第三方依赖）、可独立部署、可在 CI 中直接运行。

- 代码：`codes/ontology_check.py`（550 行，仅标准库 `os/sys/json/csv/re/glob/subprocess/collections/argparse`）
- 测试：`codes/tests/test_ontology_check.py`（各核查类单测，全绿）
- CI：`.github/workflows/ci.yml` → `ontology-check` job
- 版本：`ontology_check v1.0.0`

---

## 一、5 类核查

本体检查覆盖 **5 个核查类别**，每类独立计 0-100 子分，按权重加权得综合分：

| 类别 | 权重 | 核查内容 |
|------|------|----------|
| **A. 链路断链 `chain`** | 20% | 本体链路完整性：Web 桥接 ↔ 套件脚本 ↔ CSV ↔ NT ↔ 词典 ↔ 决策；并对代表知识库做一次**真实「CSV→本体」多表构建冒烟测试**，验证数据流 CSV→本体 无断链。 |
| **B. CSV 数据质量 `csv`** | 25% | 全库 CSV：可读性 / 空表 / 表头 / 空主键 / 重复主键 / 空单元格。 |
| **C. NT 本体质量 `nt`** | 20% | 本体产物 `output/*.nt`（本地存在时）：解析合法性 / 空文件 / 悬空实体引用；并检查构建冒烟产物的悬空引用。 |
| **D. 词典一致性 `lexicon`** | 15% | `industrial_dict/*.json`：JSON 合法性 / 空词典 / 必需键 / 空中文键 / 空英文值 / 英文值重复。 |
| **E. 本体一致性 `consistency`** | 20% | `config/relations.json` 合法性 + 对象属性 `target_class` 存在性 + 本体类声明确认。 |

### 计分规则

- 满分 100，按类别权重加权；各类别内部按问题严重度扣分：
  - `critical` 致命 = 扣 10 分；`major` 主要 = 扣 5 分；`minor` 次要 = 扣 1 分；`info` = 0。
  - 单类别扣分封顶 45 分（子分下限 55），避免单一类别噪声把总分打满归零。
- **通过条件**：`无 critical 致命问题 且 score >= threshold`（默认阈值 60，`--threshold` 可调）。
- 退出码：`0` = 通过，`1` = 不通过。

## 二、独立运行 · 零依赖 · 断链

- **纯标准库零依赖**：无需 `pip install`，装好 Python 即可运行；`setup-python` 后直接执行。
- **独立 CLI**：不依赖 Web 服务、数据库、模型，可离线一键检查整个仓库。
- **本地==CI 一致**：扫描仅统计 **git 已提交（入库）** 的文件
  （用 `git ls-files` 判定），未入库的临时产物（如运行时生成的 `output/*.nt`、
  敏感 `data/*.csv`）不计入"全库"，保证本地结果与 CI 纯净检出完全一致。
- **断链检测**：A 类对 9 个核心套件脚本 + Web 桥接 + 公共词典 + 知识库数据目录逐项探测，
  任一缺失即判 `critical` 致命；并对代表知识库执行真实 `multi_table.py` 构建冒烟，
  构建失败即判断链。

## 三、用法

```bash
# 检查当前仓库(脚本所在目录及其上级 repo 根)
python codes/ontology_check.py

# 指定 codes 目录
python ontology_check.py --dir codes

# 自定义通过阈值 + 输出 JSON 报告
python ontology_check.py --threshold 60 --json report.json

# 跳过真实构建冒烟测试(更快)
python ontology_check.py --no-build

# 查看帮助
python ontology_check.py --help
```

CLI 参数：

| 参数 | 说明 |
|------|------|
| `--dir <path>` | codes 目录（默认本脚本所在目录） |
| `--threshold <int>` | 通过阈值（默认 60） |
| `--json <file>` | 将完整报告输出到 JSON 文件 |
| `--no-build` | 跳过真实 CSV→本体 构建冒烟测试 |

## 四、CI 接入

`.github/workflows/ci.yml` 新增 **`ontology-check` job**（与现有 `test` job 并行）：

- 平台 `ubuntu-latest` + `python 3.11`
- 零依赖：仅 `actions/checkout@v4` + `actions/setup-python@v5`，**无需安装任何 pip 包**
- 执行 `python ontology_check.py --threshold 60 --json ontology_check_report.json`
  （阈值通过；exit 0 即 job 绿）
- 随后打印关键指标 `score / ok / critical / n_issues` 供 CI 日志查看

当全库通过阈值时 job 变绿；若出现致命问题或得分跌破阈值则 job 变红，阻断合并。

## 五、测试

`codes/tests/test_ontology_check.py` 覆盖 **5 类核查各核查用例 + 计分 + 阈值 + CLI**：

| 测试 | 验证点 |
|------|--------|
| `test_chain_*` | 链路断链：完整树无致命；缺 Web 桥接 / 无 CSV 判致命 |
| `test_csv_*` | CSV 质量：好表无问题 / 重复主键 / 空主键 / 空表 检测 |
| `test_nt_*` | NT 本体：合法无悬空 / 悬空引用 / 空本体 检测 |
| `test_lexicon_*` | 词典：好词典 / 缺必需键 / JSON 非法 检测 |
| `test_consistency_*` | 一致性：缺 relations.json 致命 / target_class 缺类声明 检测 |
| `test_score_category_penalty` | 计分扣分逻辑（major/critical） |
| `test_run_check_returns_report_and_ok` | 综合检查返回报告且通过 |
| `test_threshold_high_fails` | 阈值不可达则失败 |
| `test_cli_*` | CLI 退出码 0 + JSON 报告落盘 |

运行测试（在 `codes/` 下）：

```bash
python -m pytest tests/test_ontology_check.py -v --tb=short
```
