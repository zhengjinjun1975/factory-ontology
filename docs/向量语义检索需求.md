# 需求：混合检索 — 向量语义检索 + BM25 融合（提升模糊查询命中率）

> 依据《综合方案-本体问答泛化.md》混合检索章节。用户方向：检索采用语义、向量混合检索。
> 可行性已验证：本地 Ollama nomic-embed-text(768维)，语义相似度高（"最贵"vs"价格最高"0.749、"油轮"vs"船舶类型"0.954）。

## 背景
当前检索链路：规则引擎 → GraphRAG → BM25(稀疏) → miss。缺语义向量检索，无法处理语义模糊/同义/口语化查询（如"最贵的产品"→price、"油轮"→船型）。

## 目标文件
- `E:\open-source\factory-ontology-kit\codes\vector_retrieval.py`（新建，向量检索模块）
- `E:\open-source\factory-ontology-kit\codes\api_server.py`（接入混合检索）

## 要求
### 1. 新建 vector_retrieval.py（本地 embedding，nomic-embed-text）
- 建库/建图时对实体名+属性值做 embedding（调 Ollama /api/embeddings，model=nomic-embed-text）
- 存向量索引 {实体/属性值: 向量}
- 查询时 embedding 问题 → 余弦相似度召回 top-k 语义相近实体
- 纯标准库实现（调 Ollama HTTP，无第三方向量库依赖），embedding 失败回落空（不阻塞）

### 2. 接入 api_server 混合检索
- 在 BM25 之后加向量语义检索层（或与 BM25 融合）：
  - 查询 → 规则 → GraphRAG → BM25(稀疏) → 向量语义检索(embedding) → 融合 → LLM生成
  - 向量检索召回语义相近实体（解决"最贵/油轮"模糊查询）
- 本地优先，向量检索失败回落（不阻塞）

### 3. 融合策略
- BM25 分数 + 向量相似度 加权融合（简单加权或取交集），召回更全
- 极简：先做"向量检索召回 top-k + 与 BM25 取并集"，喂给下游

## 约束
- 极简，复用本地 nomic-embed-text（零 API 成本）
- 纯标准库（requests 或 urllib 调 Ollama）
- embedding 失败回落（不阻塞）
- 不破坏现有命中
