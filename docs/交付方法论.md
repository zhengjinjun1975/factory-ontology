# 交付方法论：本体建模 → 大模型落地

> 精简、可迁移。换任何工厂/领域，只换数据，立即能用。

## 一、核心思想

**大模型落地难在"领域知识"和"数据"之间没搭桥。本体建模就是这座桥：把裸表变成"实体-关系-属性"的语义结构。**

```
原始数据 → 本体建模 → 原子智能体 → 编排 → 大模型应用
```

## 二、精简化的关键：换工厂立即能用

**问答逻辑不绑定具体词表，靠词典驱动。换数据源只换词典，代码不动。**

| 层 | 是否依赖具体工厂 | 做法 |
|----|----------------|------|
| 数据→本体 | 否 | 任何 CSV 自动转本体 |
| 词典/字段 | 是 | 全自动生成(LLM推断)，换工厂换词典 |
| 问答逻辑 | 否 | 通用模板(数量/极值/范围/统计/组合/区域) |

## 三、换工厂 3 步（现场落地）

1. **转本体**：`python csv_to_owl.py data.csv output.nt`
2. **自动词典**：`lexicon_agent` 生成（或手写精简词典）
3. **直接问**：通用模板引擎 `ontology_qa_v3` 回答

## 四、六条通用经验

1. **建模是桥不是终点** — 让大模型"懂领域"，别为建模而建模
2. **原子智能体是积木** — 单一职责、可组合、可替换
3. **编排器是组织者** — 轻量调度器按任务类型路由，零依赖可部署现场
4. **泛化靠外置** — 词典/字段映射外置成配置，换领域只换配置
5. **规则兜底 + LLM 泛化** — 确定性走规则(快准)，模糊走LLM(灵活)
6. **零依赖可部署** — 纯标准库，能带到任何现场

## 五、决策准则

- 先问"数据在哪、要解决什么问题"，再谈技术
- 能自动就别手写：词典/类型推断/本体补全都自动化
- 规则能答的别让 LLM 答：省 token、快、准

## 六、现场 FDE 落地清单（最小工作量）

```
□ 数据准备: CSV(UTF-8, 英文表头, 有id列最佳)
□ 自动建模: factory_agent.py setup
□ 人工监督: 确认词典概要(关键字段中文名是否合理)
□ 自动验证: 跑示例问题确认准确
□ 培训交接: 教业务人员自然语言提问
```

## 七、已知边界（诚实）

- 数据形态：最适配结构化单表，时序/多表需扩展
- 语义校对：自动词典偶有误判，需人确认关键字段
- LLM 稳定性：本地模型偶发空响应，生产用更强模型
- 只支持 CSV：Excel/DB 需先导出
