# 交付方法论：本体建模 → 大模型落地

> 精简、可迁移。换任何工厂/领域，只换数据，立即能用。
> 定位：**开源算法原子层 + 闭源编排层**。本仓库交付的是可复用的原子（本体认知原子 / rag 原子 / 事件原子），被闭源侧编排器按需调度落地到现场。

## 一、核心思想

**大模型落地难在"领域知识"和"数据"之间没搭桥。本体建模就是这座桥：把裸表变成"实体-关系-属性"的语义结构，让规则引擎和大模型都能读懂数据。**

```
原始数据 → 本体建模 → 原子（本体认知/rag/事件） → 编排 → 大模型应用
```

## 二、域 + 原子：领域与算法解耦

这套交付方法的骨架是**「域」与「原子」分离**：

- **域（domain）**：一个工厂/行业的数据与知识，绑定具体数据、词典、schema（`data_*`、`config/`）。
- **原子（atom）**：领域无关的可复用算法单元，单一职责、可组合、可替换，代码不绑定任何具体行业。

换工厂 = 换域（换数据 + 词典 + schema），原子代码一行不动。

### 本仓库提供的原子

| 原子 | 模块 | 职责 | 编排方用途 |
|------|------|------|-----------|
| **本体认知原子** | `core/base_agent.py` + `agents/query_agent.py` + `schema_ontology.py` + `ontology_qa_v3.py` | 把结构化数据建模成本体，按 schema 规则做确定性问答（数量/极值/平均/过滤/范围/计数） | 回答业务自然语言提问 |
| **rag 原子** | `knowledge/`（ingest/embed/store/rag）+ `graph_rag.py` + `bm25_retrieval.py` + `vector_retrieval.py` | 本体引导 GraphRAG + 向量混合检索，覆盖开放式/关系/模糊问题 | 语义召回、多跳追问 |
| **事件原子** | `event_bus.py` | 数据变更的领域事件模型 + 订阅/发布（DATA_ADDED / METRIC_ANOMALY / THRESHOLD_EXCEEDED / TICKET_CREATED） | 闭源监听事件并响应（告警/工单/本体刷新/通知） |
| 模型原子 | `model_llm.py` + `config/model_config.json` | 云端/本地模型统一配置、可切换 | 统一模型接入 |
| 评测原子 | `agents/eval_agent.py` + `benchmark*.py` | 用确定性标准答案评测命中率 | 交付验收、回归 |
| 资产原子 | `api_server.py` `/api/assets/*` | 语义资产快照/回滚/版本化 | 资产版本治理 |
| 多租户原子 | `config/kbs.json` | 多企业/多 kb 隔离 | 多企业交付 |

## 三、精简化的关键：换工厂立即能用

**问答逻辑不绑定具体词表，靠词典驱动。换数据源只换词典，代码不动。**

| 层 | 是否依赖具体工厂 | 做法 |
|----|----------------|------|
| 数据→本体 | 否 | 任何 CSV 自动转本体 |
| 词典/字段 | 是 | 全自动生成(LLM推断)，换工厂换词典 |
| 问答逻辑 | 否 | 通用模板(数量/极值/范围/统计/组合/区域) |

## 四、换工厂 3 步（现场落地）

1. **转本体**：`python csv_to_owl.py data.csv output.nt`
2. **自动词典**：`lexicon_agent` 生成（或手写精简词典）
3. **直接问**：通用模板引擎 `ontology_qa_v3` 回答

## 五、六条通用经验

1. **建模是桥不是终点**：让大模型"懂领域"，别为建模而建模
2. **原子是积木**：本体认知 / rag / 事件原子单一职责、可组合、可替换
3. **编排器是组织者**：开源给出算法原子，闭源侧按需调度组合，零依赖可部署现场
4. **泛化靠外置**：词典/字段映射外置成配置，换领域只换配置
5. **规则兜底 + LLM 泛化**：确定性走规则(快准)，模糊走LLM(灵活)
6. **零依赖可部署**：纯标准库，能带到任何现场

## 六、决策准则

- 先问"数据在哪、要解决什么问题"，再谈技术
- 能自动就别手写：词典/类型推断/本体补全都自动化
- 规则能答的别让 LLM 答：省 token、快、准

## 七、开源算法 + 闭源编排：边界

**本仓库是开源算法原子层，闭源是开发方服务甲方用的编排层。** 两者分工清晰：

| 边界 | 开源侧（本仓库） | 闭源侧（编排） |
|------|------------------|----------------|
| 内容 | 本体认知 / rag / 事件等算法原子，免费、可下载、可自部署 | 建模流程编排、人在环确认、反馈学习、交付打包 |
| 调用方式 | 直接命令行 / REST API 调用 | 通过 REST 或原子接口编排调度 |
| 数据 | 数据不出厂，全在工厂本地流转 | 服务完甲方即走，闭源代码不留存甲方 |
| 产出 | 本体 / 词典 / 语义资产 | 定制语义资产 + 交付报告 |

甲方拿到的是：可独立运行的开源算法 + 交付产物，不依赖闭源服务也能长期自维护。

## 八、现场 FDE 落地清单（最小工作量）

```
□ 数据准备: CSV(UTF-8, 英文表头, 有id列最佳)
□ 自动建模: run.py setup
□ 人工监督: 确认词典概要(关键字段中文名是否合理)
□ 自动验证: 跑示例问题确认准确
□ 培训交接: 教业务人员自然语言提问
```

## 九、已知边界（诚实）

- 数据形态：最适配结构化单表，时序/多表需扩展
- 语义校对：自动词典偶有误判，需人确认关键字段
- LLM 稳定性：本地模型偶发空响应，生产用更强模型
- 只支持 CSV：Excel/DB 需先导出
- **原子化边界**：本仓库交付的是可复用的算法原子与确定性内核；完整的自动化编排、反馈学习循环由闭源侧实现，开源侧不包含也未证实该能力
