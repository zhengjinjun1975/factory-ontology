# 需求：数据输入端增强 — 多文件建模 + 数据库接入

> 用户反馈："数据输入端增加多文件浏览、选择、确认，进行本体建模，增加数据库接入。"
> **场景约束：本地厂区局域网**——数据都在厂区本地局域网，数据库接入连的是局域网内 MES/ERP/台账服务器（MySQL/PostgreSQL），数据本地处理、不出厂（与项目"全本地化"定位一致）。不走公网。
> 遵循代码极简原则 + 复用优先（复用现有 db_loader.py 和 schema_ontology 多表建模）。

## 优化1：多文件浏览/选择/确认/建模（统一入口，重做数据输入区）
**用户明确反馈**："示例数据和数据文件选择功能很奇怪，应该只有一个；文件按钮没能浏览文件、选择多文件、确认多文件，然后再建模。" → 重做数据输入区为**单一入口**。

要求：
1. **去掉"示例数据"独立下拉 + 单文件输入的两套混乱设计**，统一成一个"数据文件"区
2. **多文件浏览**：`<input type="file" multiple accept=".csv,.json">`，点按钮弹出系统文件选择器，可选多个 CSV/JSON
3. **文件列表 + 确认**：选后显示文件列表（文件名 + 大小 + 移除按钮），用户确认后点「确认并建模」
4. **一键建模**：确认后批量上传（setupOntologyMulti）→ 统一建多表本体 → 显示建模结果
5. **示例数据作为辅助**（可选保留）：若保留示例，放在"或选择示例"次级位置，不干扰主流程；或干脆移除示例下拉，仅保留多文件主入口（优先按用户"应该只有一个"）
6. 后端已就绪：POST /api/ontology/setup-multi（多文件）已验证

## 优化2：数据库接入（本地厂区局域网）
要求：
1. 前端数据输入区加"数据库接入"折叠区：数据库类型（MySQL/PostgreSQL）+ 主机/端口/用户/密码/库名 + 表名（可多个，逗号分隔）+ 「连接并建模」按钮
2. 后端新增 `dbSetup(cfg)`：复用 db_loader.load_db 读指定表 → 数据写入 data/ → schema_ontology 多表建模
3. 缺驱动（pymysql/psycopg2）时清晰报错提示安装
4. 极简：复用 db_loader.py，不重写连接逻辑

## 铁律
1. **极简**：复用现有 schema_ontology（多表建模）+ db_loader（DB连接），只加必要的 UI 和桥接
2. **Svelte 5**：$state/$props，不用 export let
3. **不破坏现有**：单文件上传/示例数据/问答/看板正常

5. **浅色工业风**：折叠区/表单符合现有风格
