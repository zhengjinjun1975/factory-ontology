# 规模化指南 — 从内存图到图数据库

本系统的图是**内存图**（`graph_rag.build_graph`），中小规模台账级（≤10 万实体）够用。
更大规模需升级图存储。分三档：

## 规模档位

| 规模 | 方案 | 说明 |
|------|------|------|
| ≤10 万实体 | 内存图（当前） | 每次启动从 .nt 重建（快），无需额外存储 |
| 10万-100万 | **SQLite 图存储**（`graph_store.py`） | 持久化图，跨重启复用、加载快于全量重建 |
| 100万+ | 真实图数据库 | Neo4j / LightGraph / JanusGraph |

## 一档：内存图（当前，默认）

```bash
python api_server.py   # 启动时 build_graph(food.nt) 建内存图
```
适用：单企业台账、<10 万实体。零依赖、启动即用。

## 二档：SQLite 图存储（10万-100万）

```bash
# 一次性持久化(把 food.nt 的图写入 SQLite)
python graph_store.py codes/output/food.nt graph.db

# 应用侧: 用 graph_store.load(graph.db) 替代 build_graph()
```
- 优点：图跨重启复用，不用每次解析 .nt；SQLite 标准库零依赖
- 局限：仍加载进内存，100 万+ 会吃内存

## 三档：真实图数据库（100万+）

**Neo4j**（推荐，Cypher 查询成熟）：
- `docker run -p 7687:7687 neo4j`，用 Cypher 建图 + 查询
- 需把 graph_store 的图写入逻辑换成 Neo4j 批量导入（`LOAD CSV`）
- 查询走 Cypher（图遍历/多跳），比内存图更省内存、支持并发

**LightGraph**（国产轻量，内存图数据库，适合单机大图）：
- 纯 C++ 内存图，单机可扛千万级

**迁移要点**：
- 接口抽象：`graph_store.load()` 返回 `(graph, labels, value_index, reverse)`，与 `graph_rag.build_graph()` 同构——换后端只需替换加载函数，`find_seeds`/`extract_subgraph`/`answer_graph` 无需改
- 图数据库层只替换"建图/查图"，问答逻辑（规则引擎 + GraphRAG）不变

## 多租户（多企业，T-D1）
`config/kbs.json` 注册多个知识库，每企业独立数据目录/词典；`FOOD_KB` 切换激活：
```json
{ "kbs": { "food": {"data_dir":"data", "lexicon":"lexicon_food_products.json"},
            "企业B": {"data_dir":"data_kb_b", "lexicon":"lexicon_kb_b.json"} } }
```
`GET /api/admin/kbs` 列出；`POST /api/admin/sync` 实时同步当前 KB。

## 实时数据（T-D2）
`POST /api/admin/sync`（admin）：重读当前 KB 数据目录 + 重建本体；KB 配置 `source` 时先 `data_import` 从外部源（Excel/DB）导入。定时可配 cron 调 `/api/admin/sync` 或 `data_import.py --schedule`。
