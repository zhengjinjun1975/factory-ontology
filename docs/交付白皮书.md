# 工厂智能体交付白皮书

## 本体驱动的现场数据问答系统（FDE 现场落地）

> 版本：v1.0 | 定位：给工厂/制造现场提供"数据即答"的能力 —— 在人的简单监督下自动建模，用自然语言问任何结构化数据。

## 一、要解决的工厂实际问题

工厂现场普遍存在三座大山：

| 痛点 | 现状 | 代价 |
|------|------|------|
| **数据看不懂** | MES/SCADA/台账数据躺在系统里，业务/运维人员不会 SQL | 决策靠老师傅经验 |
| **信息难找** | 想查"哪台设备要维护/报警"要翻系统、找 IT 人 | 效率低、响应慢 |
| **知识断层** | 老师傅退休带走经验，新人上手慢 | 知识流失 |

**核心价值**：把任意结构化数据变成"会说人话的智能体" —— 业务人员用自然语言提问，立即得到答案。

## 二、方案：本体驱动的自动建模 + 自然语言问答

```
┌─────────────────────────────────────────────────┐
│  用户: "哪台设备要优先维护?" "报警的空压机有几台"   │
└──────────────────────┬──────────────────────────┘
                       ▼
        ┌─────────────────────────────┐
        │      问答引擎 (ontology_qa_v3 + graph_rag) │
        │  ① 自动建模(本体+词典)       │
        │  ② 规则引擎(确定性)          │
        │  ③ LLM兜底(语义泛化)         │
        └─────────────────────────────┘
                       ▲
                       │ 数据(CSV/MES导出)
        ┌──────────────┴──────────────┐
        │   现场数据: 设备台账/传感器/工单 │
        └─────────────────────────────┘
```

## 三、交付内容

| 模块 | 说明 |
|------|------|
| **run.py / ontology_qa_v3** | 一站式入口：自动建模 + 问答 |
| **csv_to_owl.py** | 数据→本体（零依赖） |
| **ontology_qa_v3.py** | 通用问答引擎（规则+词典驱动） |
| **lexicon_agent.py** | 全自动词典生成（LLM 推断字段语义） |
| **方法论** | 换工厂 3 步，零手写 |

## 四、现场落地流程（FDE，最小工作量）

```
第1天  现场: 导出数据(CSV) + 确认数据字典
第2天  部署: python run.py setup data.csv
第3天  监督: 确认自动生成的词典概要(人工校对关键字段)
第4天  验证: 跑示例问题确认准确
第5天  交付: 培训用户用自然语言提问
```

**人只需做一件事**：在词典概要确认那步，检查自动生成的字段中文名是否合理。

## 五、实测验证（真实数据）

用 UCI AI4I 2020 预测性维护数据集（1 万条真实制造设备传感器 + 故障）验证：

| 指标 | 结果 |
|------|------|
| 数据规模 | 10,000 条 / 14 列 |
| 自动建模时间 | <2 分钟 |
| 全自动词典 | 12 个属性中文名自动生成 |
| 问答能力 | 数量/极值/范围/统计/组合/区域全类型 |
| 语义泛化 | 规则未命中自动降级 LLM |

## 六、诚实边界（不夸大）

| 边界 | 说明 |
|------|------|
| 数据形态 | 当前最适配"结构化台账/单表"，时序/多表需扩展 |
| 语义校对 | 自动词典偶有误判（如产品等级被当设备类型），需人确认 |
| LLM 稳定性 | 本地模型偶发空响应，生产建议用更强模型 |
| 只支持 CSV | Excel/DB 需先导出 CSV |

## 七、价值总结

**给工厂**：数据变资产，人人可问，降低运维门槛，减少停机。
**给实施方**：最小工作量（5 天现场交付），可复制到任何工厂（换数据即可）。
**给团队**：一套方法论 + 代码 + 真实案例，可继续扩展。
