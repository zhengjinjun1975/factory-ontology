# 新机器部署验收清单

> 面向新用户 / CI：在一台全新机器上逐项 ✓ 走通 **部署 → 配置 → 启动 → 建模 → 问答 → 评测 → 知识库 → 资产** 完整链路。
> 每一项都给出**真实可执行的命令**与**期望输出**。全部勾选后即视为部署成功。

## 环境要求

- Python 3.9+（推荐 3.11）
- Node.js 18+ 与 npm（仅构建 Web 前端需要）
- Git

```bash
python --version    # Python 3.9+
node --version      # Node 18+（可选）
npm --version
git --version
```

## 1. 部署 ✅

```bash
git clone <仓库地址> factory-ontology-kit
cd factory-ontology-kit

# 安装 Python 依赖（核心：FastAPI / uvicorn / requests / pydantic）
python -m pip install -r requirements.txt
```

或直接跑跨平台启动脚本（自动装依赖 + 构建前端 + 启动）：

```bash
# Linux / macOS / Git-Bash
./start.sh
# Windows
start.bat
```

> 语法自检（CI 用）：`bash -n start.sh` 无输出即脚本语法正确。

## 2. 配置 ✅

### 2.1 鉴权 Key（重要）

`api_server` 的 `/api/*` 端点**默认 fail-closed**：未配置或未匹配 `X-API-Key` 一律返回 `401`。

- 推荐显式配置环境变量后启动：

```bash
# Linux / macOS / Git-Bash
export FOOD_ADMIN_KEY="你的管理key"
export FOOD_READ_KEY="你的只读key"   # 可选
./start.sh

# Windows (cmd)
set FOOD_ADMIN_KEY=你的管理key
start.bat
```

- 若不配置：`python api_server.py` 会自动生成随机 admin key 并**打印到 stdout**，复制保存即可；对外开放前务必显式配置。

**验证**：

```bash
curl -s http://localhost:8000/health
# 期望: {"status":"ok","version":"2.1.0"}

# 无 key 访问受保护端点 → 401
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:8000/api/version
# 期望: 401
```

### 2.2 多租户知识库（可选）

`codes/config/kbs.json` 注册每个行业的知识库：`data_dir`（数据目录）、`lexicon`（词典）、`nt`（本体）、`examples`（示例问题）。默认已注册 `food` / `valve` / `ai4i` 等。

### 2.3 模型（可选）

`codes/config/model_config.json` 统一管理 LLM 与向量模型：

```json
{
  "active": "cloud",          // 改 "local" 切本地 Ollama，可全离线
  "models": {
    "local": { "type": "ollama", "base_url": "http://127.0.0.1:11434/api/generate", "model": "ornith:latest", "api_key": "" },
    "cloud": { "type": "openai", "base_url": "https://api.deepseek.com/v1/chat/completions", "model": "deepseek-chat", "api_key": "" }
  },
  "embedding": { "type": "ollama", "model": "nomic-embed-text" }
}
```

规则引擎能答的走规则（零 token、确定性），规则未命中才走 LLM。

## 3. 启动 ✅

```bash
cd codes
python api_server.py                # 默认 127.0.0.1:8000
# 或指定端口
python api_server.py --host 0.0.0.0 --port 8000
```

**验证**：

```bash
curl -s http://localhost:8000/health
# 期望: {"status":"ok","version":"2.1.0"}

curl -s -H "X-API-Key: $FOOD_ADMIN_KEY" http://localhost:8000/api/version
# 期望: {"ok":true,"data":{"version":"0.1.6","contract_version":"1.0","features":[...],"kb":"food"},...}
```

> 现代 Web UI（Svelte5，可选）：另开终端 `cd web && npm install && npm run build && npm start` → `http://localhost:3001`。它通过 `/api/*` 调后端 `api_server`，所以两个服务可同时跑。

## 4. 建模 ✅

### 4.1 CLI（单表）

```bash
cd codes
python run.py setup data/ai4i.csv ai4i
# 期望: 生成 output/ai4i.nt 本体 + config/lexicon_ai4i.json 词典，打印词典概要
```

### 4.2 CLI（多表 schema 驱动）

```bash
python run.py setup-schema data_valve config/ontology_schema.json valve
# 期望: 生成 output/valve.nt（N-Triples）+ 打印节点/边统计
```

### 4.3 API（上传建模，供 Web / 无命令行用户）

```bash
curl -s -X POST http://localhost:8000/api/ontology/build \
  -H "X-API-Key: $FOOD_ADMIN_KEY" -H "Content-Type: application/json" \
  -d '{"kb":"ai4i","csv_path":"data/ai4i.csv","use_llm":false}'
# 期望: {"ok":true,...} ， 建模成功后该 kb 立即可问答
```

> 字段：`kb`（必填）、`csv_path`（单表）/ `data_dir`（多表）二选一、`use_llm`（可选，默认 true）。

## 5. 问答 ✅

### 5.1 CLI

```bash
python run.py ask "一共有多少条记录"
# 期望: 一共有 10000 条记录

python run.py ask "机器故障标签=1 的数量"
# 期望: 机器故障=1 的数量是 339
```

### 5.2 API

```bash
curl -s -X POST http://localhost:8000/api/ask \
  -H "X-API-Key: $FOOD_ADMIN_KEY" -H "Content-Type: application/json" \
  -d '{"kb":"ai4i","question":"一共有多少条记录"}'
# 期望: {"ok":true,"mode":"rule","answer":"一共有 10000 条记录","evidence":{...}}
```

> 规则引擎确定性回答（`mode:"rule"`），附 `evidence` 溯源（为什么是这个数）。


## 常见问题

- **`/api/*` 返回 401**：未设置或未匹配 `X-API-Key`，参照「配置」节设置 `FOOD_ADMIN_KEY`。
- **`/api/ontology/build` 返回 `需提供 csv_path 或 data_dir`**：请求体必须含 `csv_path`（单表）或 `data_dir`（多表）之一。
- **端口占用（`Errno 10048` / `address already in use`）**：8000 已被占用，用 `python api_server.py --port <其他端口>` 换端口。
- **Web UI 连不上 API**：确认 `api_server`（:8000）与 web server（:3001）都在运行；web 通过 `/api/*` 转发到后端。
