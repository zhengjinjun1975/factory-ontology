# 方法论与技术总结：本体问答泛化建模（v0.1.5）

## 一、核心方法论：两阶段泛化建模

**让本体问答系统"换任何行业数据即用"**，而非逐行业打补丁。

### 阶段一：规则 + 大模型 自动建模（覆盖 90%+）
建库时自动生成全部查询映射（data profiling + LLM）：
- **实体识别映射**（entity_cn2en）：从 suggest_schema 表名 + 中文 label 自动生成 {中文实体名: 表名}
- **极值字段识别**（numeric_fields）：data profiling 识别数值列（精度/价格/吨位/金额/容量/功率）
- **类型枚举收集**（type_cn2en）：枚举列 distinct 值自动收集
- **属性值同义词**（synonym_map）：枚举值 + LLM 生成同义词

### 阶段二：精细化人工辅助（覆盖长尾）
映射审查界面 + 词典编辑器 + 失败反馈回路，人工微调自动生成遗漏。

### 兜底：运行时 schema linking + 混合检索
规则未命中 → 查询改写 → 图谱检索 → BM25 + 向量语义混合检索。

## 三、关键解决方案

### 1. 泛化（换行业即用）
根源是查询映射硬编码 → 改"建库自动生成"：
- `_build_lexicon` 自动生成 entity_cn2en（词干+label 双源）+ numeric_fields（data profiling）
- 任意新行业实体（测线/炮点/项目/船/船坞/订单）自动可计数

### 2. 极值查询
- `_EXTREME_WORD_FIELDS`：最贵/最便宜→price、大/小→容量/吨位、高/低→温度/功率
- `_extreme_field` 自动推断对应数值字段

### 3. 语义模糊查询
- 向量混合检索（vector_retrieval.py，本地 nomic-embed-text + BM25 融合）
- "最贵的产品"→price、"油轮有几艘"→船型 语义命中

### 4. 模型配置
- model_config.json：云端 DeepSeek + 本地 ornith + 向量模型（embedding）统一配置
- api_key 脱敏，默认本地 embedding

## 四、架构分层

```
结构层（跨域通用）: 实体总数/极值/类型/过滤模板
映射层（随行业生成）: entity_cn2en/numeric_fields/type_cn2en/synonym_map/attr_cn2en
本体层（自动）: suggest_schema → 多表实体/关系/约束
检索层: 规则 → GraphRAG → BM25 + 向量语义混合
```

结构层与映射层解耦，换行业 = 重建映射层，不改结构层。
