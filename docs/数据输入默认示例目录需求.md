# 需求：数据输入默认示例数据目录（直接选示例 → 建模）

> 用户反馈："文件输入应该是默认的目录吧，直接找示例数据，企业建模？"
> 含义：数据输入区应**默认展示示例数据目录**的文件列表（data_valve/data 下的 CSV），用户直接勾选示例文件 → 一键建模，不用打开系统文件对话框导航。
> 遵循代码极简。

## 现状
- 数据建模 tab 数据输入区：`<input type="file" multiple>` 系统文件选择器（用户需自己导航到文件）+ 文件列表 + 确认并建模
- 后端已有：`GET /api/ontology/examples`（listExamples 返回示例文件列表）+ `GET /api/ontology/example?path=`（readExample 读内容）+ `POST /api/ontology/setup-multi`
- api.js 已有：fetchExamples() / fetchExample(path) / setupOntologyMulti(files)

## 目标文件
- `E:\open-source\factory-ontology-kit\web\src\App.svelte`（数据建模 tab 数据输入区）

## 要求
1. **默认展示示例数据目录**：数据输入区顶部默认加载并展示示例文件列表（调 fetchExamples()），分目录（如 data_valve / data）显示，每文件可**勾选**（多选，checkbox）
2. **直接选示例 → 建模**：勾选示例文件后，点「用所选示例建模」→ 逐文件调 fetchExample(path) 拿内容 → 组装 files 数组 → 调 setupOntologyMulti → 统一建模
3. **保留上传本地文件**：系统文件选择器（`<input type="file" multiple>`）作为"或上传本地文件"次级入口保留，不冲突
4. **默认即示例**：进入数据建模 tab 就展示示例目录，用户第一眼看到可用示例，快速企业建模
5. **极简**：复用现有 fetchExamples/fetchExample/setupOntologyMulti，只改展示和交互

## 约束
- Svelte 5（$state/$props，不用 export let）
- 浅色工业风，与现有一致
- 不破坏现有：本地文件上传/DB接入/问答/看板
- 示例勾选状态可管理（清除/全选可选）

## 验收
1. 数据建模 tab 默认展示示例目录文件列表（可勾选）
2. 勾选示例 → 「用所选示例建模」→ setupOntologyMulti 建模成功
3. 本地文件上传仍可用
4. vite build 无 error
5. pytest 29 passed
