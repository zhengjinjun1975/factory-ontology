# 部署指南：食品企业知识库（小型企业工程化落地）

面向无专职工程师的中小型食品企业，一套命令跑起来，浏览器/手机即用。

## 架构（一套部署，三层）

```
┌─────────────┐    ┌──────────────┐    ┌──────────────┐
│ 移动端 APP   │───▶│  REST API    │───▶│  食品本体知识库 │
│ (手机浏览器)  │    │  (FastAPI)   │    │  (multi_table │
│ 语音助手 CLI │───▶│  :8000       │    │   + GraphRAG) │
└─────────────┘    └──────────────┘    └──────────────┘
   APP/语音 均通过   api_server.py       构建于 data/food_*.csv
   REST API 统一调用  (托管APP + API)
```

- **API 层**（`codes/api_server.py`）：FastAPI，同一端口既供 API 又托管移动端 APP（`/` 即 APP 首页）
- **语音助手**（`codes/voice_assistant.py`）：键盘/语音输入 → API → edge-tts 中文朗读
- **知识库**：食品 6 表数据 → 多表本体 + 溯源关系

## 部署步骤

```bash
# 1. 环境（Python 3.9+）
pip install fastapi uvicorn edge-tts requests

# 2. 启动（首次自动构建食品本体）
cd codes
python api_server.py            # http://<服务器IP>:8000

# 3. 使用
#   移动端 APP：手机浏览器打开 http://<服务器IP>:8000
#   语音助手：  python voice_assistant.py "乳制品的数量"
```

## 安全（默认 fail-closed）

API 鉴权**默认 fail-closed**：未配置 key 或 `X-API-Key` 不匹配时，所有需要鉴权的接口一律返回 401（不会静默放行）。对外开放前必须显式设置环境变量：

```bash
# 只读/问答 key（必设，否则对外访问被拒）
export FOOD_READ_KEY=$(openssl rand -hex 16)
# 管理 key（admin 端点 / 重建 / 审计）
export FOOD_ADMIN_KEY=$(openssl rand -hex 16)
```

- 客户端调用时在请求头带 `X-API-Key: <key>`（前端/语音助手已内置读取逻辑）。
- 单机本机调试未设置 key 时，`api_server.py` 首次启动会生成随机 admin key 打印到 stdout，复制保存即可。
- 生产部署请配合 `--host 0.0.0.0` + 反向代理 TLS，不要把 key 写进代码或提交到仓库。

## 全本地化（离线，Ollama）

数据不出厂、完全离线运行时，用本地 Ollama 提供推理：

```bash
# 1. 安装并启动 Ollama，拉取模型（一次性）
#    https://ollama.com  装好后运行：
ollama pull ornith:latest
ollama serve

# 2. 切换模型（两种方式任选其一，二选一即可）
#   方式A：改 config/model_config.json 把 "active" 设为 "local"
#   方式B：命令行/进程环境变量 FOOD_MODEL=local
#   （代码已支持：model_llm 每个 model 自带 base_url，local 走
#     Ollama 原生端点 http://127.0.0.1:11434/api/generate，无需联网）
```

- **切换生效**：改 `active` 或设 `FOOD_MODEL` 后重启服务即可。
- **数据不出厂**：请求只打到 `127.0.0.1:11434`，任何提示词/业务数据都不经第三方云。
- **保留云端**：`cloud`(DeepSeek) 配置原样保留，随时把 `active` 切回 `"cloud"` 即恢复联网推理。
- **模型名可换**：用 `ollama pull <模型名>` 拉到别的本地模型后，把 `local.model` 改成对应名字即可（当前默认 `ornith:latest`）。

## 换成你自己的食品数据

编辑 `codes/data/food_*.csv`（产品/原料/批次/质检/设备/溯源 join 表），
删掉 `codes/output/food.nt` 后重启，即用你自己的数据建知识库。

- 溯源 join 表 `food_batch_ingredient.csv`：`batch_id,raw_id` 一行一条"批次用了哪个原料"
- 字段名保持一致即可，无需改代码（数据驱动）

## 工程化要点

| 方面 | 现状 |
|------|------|
| 一致性 | pytest 单测 + benchmark（规则引擎 100%） |
| 交付 | API + APP + 语音，一套部署 |
| 中文 | 全中文交互、edge-tts 中文语音 |
| 语音输入 | 可选（装 faster-whisper + sounddevice），未装走键盘 |
| 边界 | 内存图、台账级规模，非生产级大数据平台（见 README 诚实边界） |
