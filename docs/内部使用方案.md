# 企业内部使用方案（示例），用 factory-ontology 做企业知识管理

> 目标：用框架管企业自己的业务数据（设备/合同/文档），先内部用起来，沉淀可复用工具。本文档为通用示例，不绑定任何具体企业。

## 一、三个内部知识库场景

### KB-A：设备台账
**数据**：客户设备/设备台账（型号/参数/安装日期/保修期/维修记录/状态/客户）
**价值**：
- 问答："X 客户有哪些设备"、"保修期内的设备"、"维修次数最多的型号"
- **溯源**：设备→批次→零部件（哪批件出问题，影响哪些客户设备）
- **预警**：保修期快到期、超期未检设备

**表结构**：`equipment.csv`（id/设备名/型号/参数/客户/安装日期/保修期/状态）+ 批次/批次-部件关联表

### KB-B：合同台账
**数据**：销售/采购合同（合同号/客户/供应商/金额/签订日/交付期/回款/状态）
**价值**：问答（"Q3 到期合同"、"金额>50 万合同"、"未回款合同"）+ 财务/履约提醒

### KB-C：技术文档
**数据**：技术标准/手册/报告（文档类）
**价值**：文档问答 + 图谱关联（文档↔型号↔标准）

## 二、落地步骤（每 KB 约 1-2 天）
```
1. 建库骨架   python new_kb.py kb_a --name "设备台账" --icon "🔧"
2. 接入数据   把 CSV 放进 data_kb_a/（或 ERP 直连 db_loader）
3. 配词典     编辑 config/lexicon_kb_a.json（字段中英映射）
4. 部署       设 FOOD_KB=kb_a 启动 python api_server.py
5. 使用       📱 手机问设备/合同 · ⚙️ 管理后台 · 📄 导出
6. 验证       python data_quality.py + benchmark
```

## 三、价值与 ROI
| 场景 | 直接价值 |
|------|----------|
| 设备台账 | 库存/维护/保修查询从翻表格 → 一句话问答；质量追溯秒级定位 |
| 合同台账 | 履约/回款提醒、客户合同全景，减少漏单/逾期 |
| 技术文档 | 资料即问即答，新人上手快 |

## 四、分工
- 框架侧：已就绪（建库/词典/QA/部署）；CodeAgent 做代码审查 + 端到端测试
- 企业侧：提供脱敏业务数据、确认字段语义、部署、日常使用

## 五、优先级建议
**先做 KB-A（设备台账）**——最贴合业务、最能体现溯源价值、最容易拿到数据。KB-B（合同，财务敏感需脱敏）次之。KB-C（文档）最后。

## 六、诚实边界
- 需企业真实（脱敏）数据才能从"示例"变"实锤"——数据是唯一前提
- 内部先用起来是"采用"的起点，不等于对外产品化
