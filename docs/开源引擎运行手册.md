# 开源算法引擎运行手册（factory-ontology-kit）

> 用途：本体/词典/问答/检索/评测的算法引擎，对外提供 REST API。闭源通过 REST 调用。
> 版本：v0.1.6

## 一、启动

### 1. 依赖
- Python 3.10+
- 可选 LLM：本地 ornith（Ollama）/ 云端 DeepSeek
- 文档解析：fitz（可选）

### 2. 启动 API 服务
```bash
cd codes
set FOOD_ADMIN_KEY=你的管理key      # 必配，否则一律401
set FOOD_READ_KEY=你的只读key
python api_server.py                # :8000
```

### 3. 一键启动（含前端）
```bash
start-enterprise.bat   # 自动配 key，启动后端+前端
前端: http://localhost:3001
```

## 二、REST API 主要端点

| 端点 | 作用 |
|:--|:--|
| `POST /api/ontology/build` | 建模（data_dir 多表 / csv_path 单表）|
| `POST /api/ask` | 问答（`{kb, question}`）|
| `GET /api/eval/benchmark?kb=` | 评测命中率 |
| `GET /api/stats?kb=` | 看板统计 |
| `GET /api/ontology/structure?kb=` | 本体结构（类/属性）|
| `GET /api/ontology/graph?kb=` | 本体图 |
| `GET/POST /api/knowledge/*` | 文档知识库（RAG）|
| `GET /api/assets/*` | 资产快照/回滚 |

统一信封 `{ok, data?, error?}`，错误码 4001/4041/4091/5001/5031。
**所有端点必须带 `X-API-Key` 头，并按 kb 隔离。**

## 三、建模（核心）

### 单表
```bash
curl -X POST http://localhost:8000/api/ontology/build \
  -H "X-API-Key: KEY" -H "Content-Type: application/json" \
  -d '{"kb":"myk","csv_path":"data/equipment.csv"}'
```

### 多表（推荐，完整）
```bash
-d '{"kb":"myk","data_dir":"data_mydir"}'   # 目录下所有 csv 建多实体本体
```

建模产出：`output/<kb>.nt`（本体）+ `config/lexicon_<kb>.json`（词典自动生成）

## 四、前端（企业系统）
- 登录：admin/admin123（示例企业）
- 引导式 onboarding（企业→行业→数据 三步确认）
- 功能：问答/看板/评测/知识库/资产/建模
- 单企业收敛：登录后只看到自己企业数据

## 五、词典自动生成（强化）
- entity_cn2en：实体中文→类（设备/客户/机组等自动推断）
- type/status_cn2en：枚举值自动映射
- attr_cn2en：字段→属性
- 实体消歧：问答按实体类过滤（机组 vs 设备）

## 六、故障排查

| 问题 | 处理 |
|:--|:--|
| 401 | 未配 FOOD_ADMIN_KEY/FOOD_READ_KEY，或 X-API-Key 不对 |
| 问答返回旧数据 | 词典改了需重启后端（_get_kb_ctx 缓存）|
| 命中率低 | 补词典（entity/type/attr 映射）|
| 串台 | 确认端点带 kb 参数 |
