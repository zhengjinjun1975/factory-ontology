# 舆情系统内部完全对齐·落地设计（母本体 + 二次本体统一到 schema_ontology）

> 已实测验证可行性（不改 schema_ontology 源码）。本设计把舆情建模从"自写 csv_to_owl+enhance+手工三元组"统一到 factory schema_ontology 声明式引擎。落地前请审。

## 〇、对齐目标（用户确认：范围最大）
舆情不再自写建模执行——母本体与二次本体(事件)都通过 vendor schema_ontology 声明式建模，统一 .nt 读写与三元组风格。舆情保留：采集/情感/事件抽取/风险/预警/传导 等**领域判断**（非建模执行）。

## 一、核心洞察：行业 schema(保留) vs 建模引擎(统一)
- **保留**：`industry_schema.json` = 舆情领域建模意图(产品类型层级/对象关系语义/事件类型映射/风险参数)。这是领域资产,不删除。
- **统一**：把该意图**翻译**成 schema_ontology 的 schema(entities/relations/constraints), 由 schema_ontology 执行建模。

## 二、适配层设计：industry_schema → schema_ontology.schema

新增 `modules/align_schema.py`（舆情侧适配, 不跨库, import vendor schema_ontology）:

### 2.1 母本体(产品)翻译
| 舆情 industry_schema | → schema_ontology schema |
|---|---|
| ontology.table=mfg_products | entity{table:"mfg_products", key:"product_id"} |
| ontology.name_col | 属性 product_name |
| ontology.type_hierarchy{整车:[]..} | 每类 → 子类(整车/动力电池 作为 hasCategory 值) |
| ontology.object_relations{suppliedBy:{node_col:supplier}} | relation{id:"suppliedBy", fk:"mfg_products.supplier", to:"Mfg_products"} |
| (product_type列) | 需在数据层把 product_type rename→category(schema_ontology 只认 category 列出子类; 已实测改名后出 subClassOf) |

**翻译实现**: 读 industry_schema → 构造 schema_ontology 需要的 `{entities, relations}` → `data = {table: rows}`(行内 product_type 改名 category) → `to_nt(data, schema)`。

### 2.2 二次本体(舆情事件)声明
事件作为 schema_ontology 的一个实体类型(动态实例), 在统一 schema 中声明:
```
entity{ id:"舆情事件", table:"_events"(虚拟), attributes:[event_type,actor,impact,time,sentiment,spread,source,link...],  relation hasTarget→Mfg_products(受影响) }
```
事件实例**运行时写入**(采集→情感→抽取→作为事件实例), 用 schema_ontology 的实例生成风格(同一 NS/类型声明/字面量格式), 替代 build_event_subgraph 自写三元组。

## 四、二次本体(事件)时态差异 — 关键设计决策
schema_ontology 是**静态批量**建模; 舆情事件是**运行时增量**(每次采集新增)。方案:
- **事件实体类型声明**在 align_schema(静态)。
- **事件实例生成**复用 schema_ontology 的统一三元组风格(NS/类型/字面量/relation 目标引用), 抽成 align_schema.add_event_triples(event, matched) 替代 build_event_subgraph 的裸字符串拼接——保证风格一致、去重、可解析。
- 保留 merged.nt 的"母本体 + 事件子图"合并结构。

## 五、验收门
1. 舆情 CSV→align_schema→to_nt 产出 mother.nt: 含 子类层级(整车 subClassOf) + 对象关系(suppliedBy ObjectProperty) + 数据属性。
2. 舆情 parse_mother_nt / ontology_enhance.build_conduction_graph 读新 mother.nt 正常(兼容性)。
3. 事件 add_event_triples 写入 merged.nt → parse_events 能读(事件+targets+来源)。
4. 全链路: /api/build → /api/alerts /api/trend /api/ask /api/notify 正常。
5. factory 侧: schema_ontology 若有改动(应无,本设计不改源码) → sync_vendor + factory 78测试回归。

## 六、风险与回滚

- server.py 单文件 http.server 改后 kill 重启生效(skill 已知)。
- 若 align 不兼容(parse 读不了), 回滚到原 kb/*.nt + 原 build 路径。
