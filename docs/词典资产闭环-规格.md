# 词典资产闭环 —— 规格与设计

> 目标：把「企业词典 → 行业积累 → 反哺新企业」做成可运行、可复核的数据资产闭环。
> 本文是落地规格（接口契约 + 判据 + 验收门），配合 `scripts/verify_dict_asset_loop.py` 验收。

## 1. 三层资产

| 层 | 载体 | 生命周期 | 内容边界 |
|---|---|---|---|
| 工厂层 | `config/lexicon_<kb>.json` | 一企业一份，随建模产出 | 该厂的属性/枚举/同义词/实体映射（含工厂特有字段） |
| 行业层 | `codes/industrial_dict/01_valve_pump.json` 等 | 同行业跨企业累积 | 同行业可复用的词表（设备/部件/工艺/故障/标准） |
| 公共层 | `codes/industrial_dict/00_basis.json` | 跨行业累积 | 工业通用骨架词（设备/状态/材质/通用故障） |

优先级：**工厂 > 行业 > 公共**（下游合并时工厂层覆盖上层，上层只补工厂没有的）。

## 2. 实测断点（2026-09-16，均为实件核实）

| 编号 | 断点 | 证据 |
|---|---|---|
| D1 | 行业层写了没人读 | `_load_public(files=None)` 默认 `["00_basis.json"]`；实测建模/问答只吃到 23 type/9 status/17 synonym/10 entity，而 `01_valve_pump.json` 里躺着 22 type/20 pump/18 part/14 fault/10 standards 未被消费 |
| D2 | 合并白名单与行业层键位不匹配 | `_MERGE_KEYS` 只含 type/status/synonym/entity 四类；行业层的 `pump_cn2en`/`part_cn2en`/`process_cn2en`/`safety_cn2en`/`material_synonyms`/`standards`/`fault_cn2en` 全在名单外，即使显式合并也会被丢 |
| D3 | 吸收判据被批量生成污染 | 47 份词典里 35 份是 2026-09-02 23:21 同一分钟生成；按生成批次算独立来源只有 2 批（437 词 / 205 词，交集仅 119 词）；公共层只收 59 词，其中仅 23 词跨批出现。「出现 ≥3 份词典」实为同一模板复制 |
| D4 | 吸收口径不一 | `/api/industry/absorb` 用 `threshold=1`（单厂词全吞）；脚本 `--scan` 用 `CROSS_KB_THRESHOLD=3` |
| D5 | 无进出口 | 工厂词典无任何导出/导入端点；`/api/industry/export` 只覆盖 4 个公共文件且 `dict_export/` 从未生成；BFF 不转发 `industry/*`；前端无按钮 |

## 3. 目标数据流

```
企业A 建模 ──► lexicon_A.json ──┐
                               ├─► 吸收（独立来源判据）──► 行业层 01_<industry>.json
企业B 建模 ──► lexicon_B.json ──┘                              │
        ▲                                                      │
        └──── _build_lexicon 建模引导（工厂>行业>公共 合并）◄───┘
                │
                └─► 问答解析层 load_dict（同样三层合并）

导出：企业A 词典/整包 ──► 企业B 导入（作为起点）──► 叠加 B 的 CSV 推断（数据优先，词典补差）
```

## 4. 接口契约（本次落地）

### 4.1 `codes/industrial_dict_loader.py`（消费链）

```python
INDUSTRY_FILES = {"基础": "00_basis.json", "泵阀": "01_valve_pump.json",
                  "精细化工": "02_fine_chem.json", "地球物理": "03_geophysics.json"}

_MERGE_KEYS = ("type_cn2en", "status_cn2en", "synonym_map", "entity_cn2en",
               "fault_cn2en", "material_synonyms", "pump_cn2en", "part_cn2en",
               "process_cn2en", "product_type_cn2en", "safety_cn2en", "method_cn2en")

def industry_for_kb(kb: str) -> str | None      # 读 kbs.json 的 industry 字段；缺失按关键词兜底
def load_industry_files(industry: str | None) -> list[str]   # None → ["00_basis.json"]
def _load_public(files=None, industry=None) -> dict          # industry 生效时 = [00_basis, 行业文件]
def merge_industrial_dict(kb_dict, files=None, industry=None) -> dict
```

- **向后兼容**：`industry=None` 且 `files=None` 时行为与现状完全一致（只 `00_basis.json`），故既有验证 A1/A2 仍成立。
- `_MERGE_KEYS` 只收「中文词 → 规范名」的 flat dict，不收 attr/numeric/field_aliases 等工厂字段。

### 4.2 `codes/absorb_public_dict.py`（吸收判据）

```python
def lexicon_word_set(d, keys=_ABSORB_KEYS) -> set[tuple[str, str]]   # (词表键, 中文词)
def source_clusters(lex_paths=None, similarity=0.9, exclude_public=True) -> list[dict]
        # 同源聚类：与已有簇词集合 Jaccard >= similarity 判同源（模板复制只计 1 个来源）
        # exclude_public=True 先剔除公共/行业层已有词 —— 否则人人含公共词，Jaccard 虚高、全体误判同源
def independent_source_counter(lex_paths=None, exclude_public=True) -> tuple[Counter, dict]
        # 返回 (词 -> 独立来源数, 诊断信息：files / independent_sources / clusters)
def load_candidates() / save_candidates(d)     # 候选池 industrial_dict/_candidates.json
def promote_candidates(counter, threshold=3, industry="基础", key_map=None) -> dict
def learn_from_kb(kb_path, industry="基础", threshold=3) -> dict
        # 单企业入口：词入候选池（记来源/首见）→ 独立来源数达阈值才升级进行业层
def absorb_from_counter(counter, threshold=3, verbose=True, key_map=None) -> dict
        # counter 语义 = 独立来源数；key_map = {词: 原词表键}，优先按来源键归类（比启发式准）
def merge_into_public(public, suggestions) -> tuple[dict, bool]
```

- 判据变更理由：D3 实证「文件计数」测的是复制次数。真实不同企业的词典词集合重合度通常低（attr 字段名/枚举值不同），模板复制则 ≥0.9；用**词集合 Jaccard ≥ 0.9 判同源**比「按 mtime 分批次」更本质（不依赖文件时间戳）。
- 阈值 3 的含义：**至少 3 个独立来源**都出现该词，才收进行业/公共层。

### 4.3 `codes/dict_asset.py`（进出口，新模块，纯标准库）

```python
def verify_lexicon(d: dict) -> list[str]                  # 结构校验，返回问题列表（空=通过）
def lexicon_diff(base: dict, other: dict) -> dict         # {"added": {k: [词...]}, "changed": [...], "total": {...}}
def export_lexicon(kb: str, out_dir: str | None = None) -> dict      # {"ok","path","stats"}
def import_lexicon(kb: str, src_path: str, mode: str = "merge",
                   dry_run: bool = False) -> dict         # mode: merge|replace；返回差异报告
def build_bundle(kb: str, out_dir: str | None = None) -> dict        # zip: lexicon + schema + nt + meta.json
def restore_bundle(zip_path: str, kb: str | None = None, dry_run: bool = False) -> dict
```

- 导入校验：必须是 dict；`_MERGE_KEYS` 至少一类存在；键必须是 str；值必须是 **str 或 str 列表**（实测 `synonym_map` 的值是同义词组 list，全库 1197 条皆 list；type/entity/status 值为 str）。
- `mode="merge"`：工厂现有词优先，导入只补缺（与下游合并语义一致）。
- `dry_run=True` 只返回差异报告，不落盘。
- 落盘前自动备份 `lexicon_<kb>.json.bak_<ts>`。

### 4.4 `codes/api_server.py`（端点接线）

```
GET  /api/kb/{kb}/lexicon/export?download=1|0&bundle=0|1
POST /api/kb/{kb}/lexicon/import        body: {path|content, mode, dry_run}
POST /api/industry/absorb               判据改用独立来源；body 增加 kb 以定位行业
```

## 5. 验收门

1. `scripts/verify_ontology_lexicon_relation.py` 四库全绿，且新增断言：**行业层被真实消费**（合并 `industry=泵阀` 后 type 词数 > 只合并 00_basis 时）。
2. `scripts/verify_dict_asset_loop.py`（新）：端到端断言
   - 导出 → 导入到新 kb → 词条一致（round-trip）
   - 同源词典（复制一份）只计 1 个独立来源；异构词典计 2 个
   - 独立来源 < 阈值的词**不**被吸收；≥ 阈值的被吸收
   - 吸收后行业层词数增加，且新企业建模时该词**能进入**工厂词典（闭环真的转起来）
3. `scripts/regression_qa.py` 不回归。
4. 导入非法文件必须被拒（不是策略：非 dict / 值为非 str / 全空）。

已知取舍 / 下轮
- **BFF 未转发、前端无入口**：`web/server/index.js` 无 `/api/kb/*/lexicon/*` 与 `/api/industry/*` 路由，前端无按钮
  → 本批只做到"后端能力 + 可验证"，界面入口属下一轮（需 npm build 验收）。
- **阈值 3 是保守起点**：实测当前语料下独立来源 ≥3 的词只有 15 个（旧文件口径 61 个）。
  阈值调低要配人工复核；候选池 `_candidates.json` 已保留来源与首见时间供复核。
- **同源判定用词集合 Jaccard 0.9**：对"同一模板小改后分发"的情况敏感；更稳的升级路径是引入内容指纹 + 人工确认两段式。
- 工厂词典本身不累积（每次建模重建）；**累积发生在行业层与公共层**，这正是本闭环的设计取向。
