# 工厂本体库商业化与 AI 原生化提升方案（调研先行版）

## 〇、一句话结论

工厂本体库的**技术底子够商用**（本地部署、数据不出厂、本体驱动），真正缺的不是功能而是**商用外壳**：合规定位、可切换的数据层、多租户鉴权与授权、离线交付与资质材料。**先补这五件，再谈拓客**。培训与舆情两条线不必从零做，已有底子（`enterprise-training-fe`、`opa-monitor`）等的是同一套外壳。

---

## 二、全网对标要点（三份研究报告，共 266 条真实 URL）

### 2.1 企业内训（报告：`企业内训商业化与AI原生化-研究.md`，37 KB）

- **产品格局**：Docebo、Cornerstone、SAP SuccessFactors Learning、北森、云学堂（绚星）、平安知鸟、职行力、知学云、UMU、EduSoho、酷学院。**2025 是拐点年**：北森 1.8 亿收购酷学院；云学堂更名绚星智慧科技（2025 营收 3.40 亿元 🟡）。
- **集体叙事**：国内头部都已转向"N 个 AI Agent 覆盖 萃-学-练-考-评"。
- **AI 五件套已收敛**：AI 做课 / 陪练 / 学伴 / 考试 / 能力诊断。
- **⚠️ 两个坏消息（对我们反而是机会）**：① **国内无一家公开用 OWL/RDF 本体做能力点图谱**，各家"胜任力模型"仍是人工标签；② **自适应路径与企业侧知识追踪"纸面强、落地虚"**，只见 BKT/DKT/LFKT 论文，无企业级 A/B 数据；所有"提效 X%"都是厂商口径，**无第三方审计**。
- **定价**：国内 SaaS **¥2,680–¥69,800/年**（版本制，按人年基本不公开）；海外按 MAU/RAU，**Docebo 成交中位数 $41,651/年**（区间 $21k–$102k 🟡）。

### 2.2 舆情监控（报告：`舆情监控商业化与AI原生化-研究.md`，36 KB）

- **产品格局**：识微、蚁坊、蜜度（新浪舆情通）、清博、拓尔思 TRS、百度智能云、人民在线、慧科、智慧星光、中科闻歌。**阿里云无自研舆情产品线**，云市场只挂第三方商品。
- **AI 可靠的**（有公开数字）：情感分析最优 **94.3%**；Qwen2.5-72B **88.3%**；DeepSeek 成本约 **$0.002/千条**；传播路径查全 **92.17%**。
- **AI 明确不可靠的**（要写进我们的产品话术，别跟风吹）：**讽刺识别仅 71%**；大模型幻觉三条路径（误报 / 漏报 / **编造情报**）；**AI 研判不能直接采信**；"舆情预测准确率 95%"这类腾讯云 SEO 稿已列为排除项。
- **定价（含 7 条 🟢 政府招标实价）**：罗湖法院 7 万、湖南水运 19.48 万、吉林市监 20.2 万 / 7.8 万、三明 4.9 万等；TOOM 按"关键词×节点"计费。
- **市场规模四个口径互相打架**（87 / 110 / 498.93 亿），报告如实并列，不取单一数字。

### 2.3 商用化基础设施（报告：`商用化基础设施(MySQL鉴权多租户计费)-研究.md`，31 KB）

- **SQLite→MySQL**：9 维方言差异（类型 / 布尔 / 日期 / 自增 / UPSERT / JSON / 并发 / 隔离级别 / 索引前缀）；迁移工具链（Dumpling+Lightning、pt-osc / gh-ost、Canal / DataX / Flink CDC）；**双写 → 灰切读 → 切写**；对账三法（行数 / hash / 逐行）。
- **鉴权**：JWT / OAuth2 / SSO / LDAP 在私有化场景的取舍表；OWASP JWT 基线 + 刷新令牌轮替；**MySQL 无原生 RLS，多租户行级隔离必须在应用层强制**；审计日志法定 **≥6 个月**。
- **License**：机器码绑定、按节点 / 并发 / 年授权、到期停用 vs 永久回退；**非对称签名离线验签** + 防篡改 + 防回拨。
- **交付**：Docker Compose 优先、K8s 按需；离线安装包；Prometheus+Grafana+Alertmanager 最小集。
- **合规**：等保 2.0（GB/T 22239-2019）；**三级及以上须做密评**（GM/T 0054-2018 / GB/T 39786-2021）。
- **政企**：信创名录已停更；国产数据库达梦 / 金仓 / OceanBase；**数据不出域**——《数据安全法》下的合规卖点，正好是我们的强项。
- **报告给的技术路线**：P0 = 方言适配层 + SQLite 加固 + License 签验；P1 = 审计日志 + 多租户 + 离线交付；P2 = MySQL 可选后端 + 信创适配 + 认证材料。

## 三、我们的优势（逐条显性列出，不打埋伏）

1. **本体驱动是真的，且国内没人这么公开做**：能力点图谱用 OWL/RDF 建模，同行还是人工标签。这是我们唯一的"人无我有"，也是最需要客户教育的点。
2. **数据不出厂能兑现**：纯本地、不调外部服务，正面接住《数据安全法》的"数据不出域"要求，舆情线的采集合规风险也天然小一截。
3. **一次外壳，三条产品线**：工厂本体 + 企业内训 + 舆情监控共用同一套鉴权 / 多租户 / License / 交付，边际成本极低。
4. **已有容器化交付与文档体系**：Docker Compose、部署文档、测试方案都在，离"能交钥匙"只差离线包与升级链。
5. **反幻觉是我们能打的差异点**：舆情同行被"编造情报"咬住，我们的确定性规则 + 本体约束正好对着这个软肋说事。

|---|---|---|---|

## 四、差距清单（G1–G10）

| 编号 | 差距 | 说明 | 影响 |
|---|---|---|---|
| G1 | 无方言适配层 | SQLite 与 MySQL 混着改，迁移无对账门 | 交付哪种库都要改代码，返工 |
| G2 | 鉴权只有 Bearer | 无角色、无租户隔离、无审计留存 | 多客户共用即串数据，政企过不了 |
| G3 | 无 License 机制 | 私有化交付后无法控授权期与规模 | 收不到钱，也没法按规模计价 |
| G4 | 合规边界未钉死 | 私有化 vs 公有云的备案义务没写进产品 | SaaS 版一上线就踩备案 |
| G5 | 考试防作弊有合规风险 | 《人脸识别办法》(2025-06-01) 禁唯一验证与联网传输 | 培训线卖点变风险点 |
| G6 | 自适应无硬数据 | 只有概念，无 A/B 对照 | 讲不出效果，只能拼价格 |
| G7 | 员工能力画像定位含糊 | 触发个保法 13(二)/24/28/55 敏感信息与自动化决策 | 客户法务一票否决 |
| G8 | 缺资质材料 | 软著、检测报告、等保、密评 | 进不了政企短名单 |
| G9 | 交付链不成套 | 无离线安装包、无升级迁移、无备份恢复演练 | 现场交付靠人肉，规模化不了 |
| G10 | 定价无三轨 | 只有"买断"思路，缺 SaaS / 订阅 / 按量 | 丢单在报价环节 |

## 五、优化方案（P0 / P1 / P2）

| 优先级 | 事项 | 现状 → 目标 | 效益 | 成本 |
|---|---|---|---|---|
| **P0** | 合规定位钉死 | 含糊 → 明示"私有化为主、公有云才备案"，产品文档与合同条款同步 | 避免上线即违规 | 低（文案+条款） |
| **P0** | 方言适配层 + 对账门 | SQLite 硬编码 → 单点方言层，能跑 SQLite/MySQL 双引擎并对账 | G1 消除，迁移可交付 | 中（1 处抽象 + 门） |
| **P0** | License 签验 | 无 → 机器码绑定 + 非对称签名离线验签 + 到期降级 | 能收钱、能按规模计价 | 中 |
| **P0** | 人脸防作弊合规改造 | 人脸为唯一验证 → 改为可选辅助 + 不联网 + 本地比对，或换行为核查 | 卖点变合规 | 低 |
| **P0** | 能力画像定位 | 直接输出评价 → 定位为"辅助诊断"，结论由人定，留痕 | 过客户法务 | 低 |
| **P1** | 鉴权升级 + 多租户 | Bearer → JWT + RBAC + tenant_id 贯穿 + 应用层行级隔离 + 审计≥6 月 | G2 消除，多客户可共用 | 中 |
| **P1** | 等保二级 + 信创适配清单 | 无 → 出清单与整改项 | 进政企短名单 | 中 |
| **P1** | 三轨定价 | 单轨 → SaaS 订阅 / 私有化买断 / 按调用量，各带锚点 | G10 消除 | 低 |
| **P1** | 离线交付链 | 单机 Docker → 离线安装包 + 版本升级 + 备份恢复演练 | G9 消除 | 中 |
| **P2** | 自适应 A/B 对照实验 | 无数据 → 出一份可公开的对照数据 | 把"纸面强"变硬数据 | 中高 |
| **P2** | 打"招聘/绩效/盘点"通链卖点 | 单点工具 → 能力点贯通人才全链 | 提高客单价 | 高 |
| **P2** | 本地小模型降 AI 成本 | 云端调用 → 本地小模型接管辅助任务 | 降本 + 更合"不出厂" | 中 |

## 六、商业化落地步骤（含你点名的 MySQL 与鉴权）

**第 1 步 · 定位与合规先钉死（1 周内可完成，不动代码）**
私有化优先、公有云才触发算法备案与安全评估（《生成式AI暂行办法》第 2/17 条）；人脸防作弊按《人脸识别办法》(2025-06-01) 改造；能力画像写成"辅助诊断、结论由人定"。**合规不先钉死，后面所有代码都可能白做。**

**第 2 步 · 数据层：加方言适配层，MySQL 变成"可选后端"**
不动现有 SQLite 默认，只把 SQL 收口到单点；补齐 9 维方言差异（自增 / 布尔 / 日期 / UPSERT / JSON / 并发 / 隔离子级 / 索引前缀）；迁移走**双写 → 灰切读 → 切写**，配**对账门**（行数 + hash + 逐行）；回滚保留旧库只读。做完这一步，客户要 MySQL（或国产库）不再返工。

**第 3 步 · 鉴权与多租户**
Bearer 升级为 JWT（含刷新轮替，按 OWASP 基线）；角色到 RBAC；`tenant_id` 贯穿全表；**MySQL 无原生 RLS，行级隔离必须在应用层强制**（一层统一入口写死，别指望数据库）；审计日志按法定留存 **≥6 个月**，且要能导出给甲方。

**第 4 步 · License 与计费**
机器码绑定 + 非对称签名离线验签（场内无私钥，验不出就不启动）；按**节点 / 并发 / 年**三选一授权；到期策略二选一（停用 或 永久回退到只读）；调用量计量做成可在离线环境对账的台账。

**第 5 步 · 交付与运维**
Docker Compose 优先（K8s 按需），出**离线安装包**；升级走带校验的迁移脚本；备份恢复要**演练过**并留记录；监控最小集 Prometheus + Grafana + Alertmanager。

**第 6 步 · 资质材料**
软件著作权、检测报告、等保 2.0（二级起步）；**三级及以上必须做密评**；信创适配清单（达梦 / 金仓 / OceanBase + 国产 CPU / OS）。这些是政企短名单的入场券，不是加分项。

**第 7 步 · 定价与卖点（卖结果，不卖功能）**
三条线各自定价：培训线对齐国内 SaaS **¥2,680–¥69,800/年**与海外 MAU/RAU 逻辑；舆情线对齐 7 条政府招标实价区间（4.9 万–20.2 万级）；本体授权按节点/年。卖点只讲可量化价值：返工率、人力工时、停机损失、合规风险。

**第 8 步 · AI 原生化（差异化收口）**
本体做能力点图谱（对标各家人工标签）+ 反幻觉设计（确定性规则 + 本体约束 + 模型只出建议）+ 自适应 A/B 对照数据。**别跟风吹"AI 预判/提效 X%"**——舆情报告里已证实讽刺识别仅 71%、大模型会编造情报。

## 七、落地顺序与依赖

```
第1步(定位/合规) ──┬──▶ 第2步(方言层+MySQL) ──▶ 第5步(离线交付) ──▶ 第6步(资质) ──▶ 第7步(定价)
                   └──▶ 第3步(鉴权+多租户) ──┴──▶ 第4步(License/计费)
第8步(AI原生化) 与 第2–5 步并行，最后才对外讲效果数据
```
- 第 1 步是**一切的前置**，不碰代码就能做，收益最高。
- 第 2、3 步是**技术底座双件**，建议同一批次做（都要动数据访问层）。
- 第 4 步依赖第 3 步（要知道"谁在用"才能授权给谁）。
- 第 6 步依赖第 2–5 步全部落定（检测报告要拿成品去测）。

---

## 八、结论

1. **先做第 1、2、3 步**：不写代码就能把合规讲清，然后把数据层与鉴权这两块底座补齐——它们同时服务工厂本体、企业内训、舆情三条线，是投入产出最划得来的一段。
2. **优势要主动讲出来**：本体驱动、数据不出厂、反幻觉，这三条是同行公开材料里没有的，别再埋在功能列表里。
3. **效果数据要靠自己造**：全行业"提效 X%"都没第三方审计，谁先给出可复现的对照数据，谁就先赢得专业客户。
