# 需求：提升检索命中率与正确率（修复 type_cn2en 空 / 字段名不一致 / 子图范围）

> 全面端到端测试基线：检索命中 9/10(90%)，确定性规则回答 8/10(80%)。
> 目标：修复短板，提升命中率与规则正确率。

## 测试发现的 3 个问题

### 问题1：type_cn2en 为空（按类型查询走 LLM 而非规则）
- 词典 type_cn2en 是空的 {} → "机加设备的数量" 走图检索而非规则计数
- 修复：multi_model._build_lexicon 生成 type_cn2en（从 suggest_schema 的枚举属性 device_type/type 推断：设备类型值→中文，如"机加设备"→机加设备）

### 问题2：字段名驼峰/下划线不一致（极值/过滤模板不命中）
- 本体字段是驼峰 powerKw，词典 attr_cn2en 映射"功率(kW)"→power_kw（下划线）
- 规则引擎极值模板（_is_max）用词典匹配字段名，但 power_kw ≠ powerKw → "功率最大的设备"不命中
- 修复：ontology_qa_v3 的 _field/_find_attr 兼容驼峰/下划线（power_kw ↔ powerKw）；或词典 value_fields 里补驼峰

### 问题3：图检索子图不含产品材质属性（不锈钢阀门走 LLM 兜底且答不上）
- 产品有 body_material（CF8/304），但 GraphRAG BFS 子图不含该属性 → "不锈钢材质的阀门" LLM 说信息不足
- 修复：graph_rag 的 BFS 子图提取应包含实体的全部属性（数据属性），或 find_seeds 命中后子图含属性值
