# 本体建模是否提升知识问答命中率？， 对照评测实证

> 方法论文（对应研究问题：本体建模提升知识检索/问答命中率）。实证数据可复现（`benchmark.py`）。

## 一、研究问题

**本体建模（把裸表转成"实体-关系-属性"语义结构）相比直接把数据喂给大模型，是否提升结构化知识问答的命中率？**

## 二、方法（可复现设计）

为避免"手写标准答案"的主观性，评测从**源数据用确定性逻辑计算标准答案**：

1. 从源 CSV 用确定性规则算出标准答案（数量/极值/平均/总和/过滤计数）
2. 同一批问题跑两条路径：
   - **A. 本体规则引擎**（ontology_qa_v3，零模型、确定性）
   - **B. 纯 LLM**（把源数据行喂给模型，不加本体）
3. 数值容错模糊匹配算命中率

## 三、实证结果

### 食品企业知识库（8 产品，9 个问题）

| 指标 | 本体规则引擎 | 纯 LLM |
|------|-------------|--------|
| 命中率 | **9/9 = 100%** | **7/9 = 78%** |
| 提升 |：| **+22 个百分点** |

纯 LLM 失败项：**平均值、总和**（计算类，LLM 算错），典型的大模型计算幻觉。

### 其他领域（本体规则引擎，零模型）

| 领域 | 数据集 | 命中率 |
|------|--------|--------|
| 制造业(预测性维护) | UCI AI4I (10000 行) | 61/61 = 100% |
| 图书库存 | library_inventory | 13/13 = 100% |
| 能源电站 | energy_station | 13/13 = 100% |
| 食品企业 | food_products | 9/9 = 100% |

## 四、为什么规则引擎赢

1. **确定性**：聚合/极值/过滤是精确计算，本体规则引擎按定义算，结果可复现；LLM 靠概率生成，计算类易错（平均/总和/大数）
2. **零 token**：结构化查询不调模型，零成本、快、准
3. **换领域即复用**：词典驱动，换任何 CSV 都 100%（4 领域实证）

## 五、结论与边界

**结论**：对结构化知识问答，本体规则引擎（确定性）显著优于裸 LLM（+22pp），且零 token、可复现。**"本体建模提升检索命中率"得到实证支持**。

**边界（诚实）**：
- 本评测覆盖**结构化查询**（数量/极值/平均/过滤/范围）；**开放式/关系/模糊问题**不在规则引擎射程，需 GraphRAG 层（图检索 + LLM）或 LLM 兜底
- 纯 LLM 未做提示工程调优（零样本直接问），更强提示/RAG 可能拉高其命中率
- 数据规模小（台账级），不涉及大规模语义检索

## 六、可复现

```bash
cd codes
python benchmark.py data/food_products.csv --llm     # 本体 vs 纯LLM (+22pp)
python benchmark.py data/ai4i.csv                     # 制造业 100%
python benchmark.py data/library_inventory.csv        # 图书 100%
python benchmark.py data/energy_station.csv           # 能源 100%
```

## 七、方法论含义

"规则优先 + LLM 泛化"是最优分工：**结构化走规则（准、省、可复现），开放式走 GraphRAG/LLM**。这比"全交给大模型"更可靠、更便宜，是中小企业在无 GPU/低成本下落地 AI 的关键路径。
