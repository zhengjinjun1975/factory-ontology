# factory-ontology 深度研究：中小企业数智化一条思路？（综合评估报告）

> 方法：四路并行研究（①arXiv/学术论文 ②GitHub 开源竞品实测 ③中国 SME 数字化现状 ④主线程竞品硬数据核查），所有 star 为 2026-09-03 GitHub API 实测，论文均带可查来源。本报告为综合定稿，三份原始研究已归档 docs/research/。
> 核心问题：轻本体 + FDE，能否为数字化程度低、组织非标、流程非标、管理混乱的中小制造企业，找到一条数智化思路？

---

## 一、总判断（一句话）

**能，而且是社区里几乎没人占据的真空白。** 中小企业数智化失败的根因不是缺工具，而是缺"可信、可问、可溯源的数据底座"；主流方案（重型MES/ERP、工业互联网平台、咨询式交付）全隐含"流程标准化 + IT承接"前提，与中小企业现实冲突。factory-ontology 的"台账先行 → 轻本体固口径 → 自然语言可问可溯源"恰好走阻力最小的切法，且这是开源生态的真空带。

---

## 二、研究证据三支柱

### 支柱1：学术（轻本体正当性成立）
- **轻量本体定义**：受控词汇/SKOS 光谱，工程实践多止步 taxonomy 即达目的（Neuhaus 2023, DOI 10.3233/AO-230072）
- **"够用最小语义 > 完备OWL"有成熟论证**：GACS（Baker 2019, npj Science of Food, PMC6751214）在跨语种大规模农业场景论证受控词汇承载的最小语义利于落地，不必全形式化
- **轻量约束大幅拉高LLM命中**：OBQC+LLM Repair（arXiv 2405.11706）只用 domain/range 轻量公理即把裸LLM准确率从16%提到72%（最难格+25.48%）；临床本体GraphRAG约98%
- **本体驱动GraphRAG**：SAT-Graph RAG（arXiv 2505.00039）明确"确定性、可审计"作卖点，与本项目确定性路由同构
- **SME模块化本体**：ETASR 13(6):12271 论证制造SME用模块化、够用即止
- **重要诚实标注**："规则100% vs 裸LLM 78%"这组数字未检索到论文原生给出，属本项目自测；学术证据是"逻辑一致 + 数量级支持"，非精确数值对照

**空白判断**：主流全在"LLM抽文档图"或"LLM写SQL"两条不可保证正确的路上；"显式本体schema固化口径 + 规则引擎确定性 + 换行业只换配置 + 零依赖"这条开源几乎无真竞品。唯一要防御的伪竞品是"客户自购RDBMS直接写SQL视图"（需论证本体层"改表不返工+口径单一源"的价值）。

### 支柱3：中国SME现实（台账先行是正确切入）
- 信通院余晓晖权威诊断：中小企业"不想/不会/不敢转"，改造均价比承受力高一个量级（~150万）
- MES渗透：CIMA 3~5% / 赛迪 37.2%但中小厂<26%，方向一致指向"中小厂靠纸质/Excel"
- 重型MES/ERP/平台失败归因：流程断点/非标/缺IT承接——隐含"流程已标准"前提
- 低代码实证：一汽大众500低代码开发者90%是一线业务人员——证明一线能建台账
- 但低代码只建"孤岛表单"建不起"关联一致可问的数据系统"——恰是轻本体空白
- Codewave实践：设备数字化"先台账底座→再流程→后分析"是阻力最小切法

## 四、竞品定位一句话

**"不是又一类文档RAG 或 Text-to-SQL，而是可被中小企业自持的、用轻本体把散乱台账固化成'可问可溯源数据底座'的确定性问答引擎。"**

护城河 = 确定性 + 换行业换配置 + 零依赖数据不出厂 + 证据溯源（四者组合在开源无同款）。最大概念参照物 Semantica（11.7k★）证明了叙事需求真实，但它重平台向监管；我方打它的"轻量可交付"空白。

## 五、未来发展方向（含优先级）

**P0 商业化信任前提**
1. 溯源做**审计闭环服务化**（哈希链已有，接 export/PROV-O 到产品，对标 Semantica 的 FDA/SOX/HIPAA 叙事）——已起步，收尾成"审核可追责"卖点
2. **Schema SSOT 收敛**（三套建模引擎归一）——长期债
3. 多租户运营层（计费/配额/企业开通）——SaaS化前提

**P1 竞争力**
4. 关系引导接线到生产（宣称的核心能力）
5. 文档对齐 + 价值锚点演示（针对"强监管溯源行业"做验收demo）
6. Web 可视化分析（中小厂爱看趋势图）

**P2 规模化**
7. 2-3 个真实行业标杆案例（非合成数据）
8. 社区运营/star增长（当前是真空，先发有先手）

## 六、结论：轻本体 + FDE = 中小企业数智化一条思路？

**回答：是，且是目前证据下阻力最小的一条。** 但要清醒界定边界：

**成立的三个理由（有证据）**
1. 主流方案集体错配（流程标准化前提 × 中小企业流程非标），已系统性证实
2. 台账先行被实践支持（Codewave）且阻力最小（不改作业只平移记录），监管行业溯源即刚需
3. 轻本体固口径 + 自然语言可问，恰好补低代码"孤岛表单"到"可问数据系统"的断裂

**必须诚实的三条边界**
1. 它替代的是"台账的关联与可问"，**不是也不应假装替代**MES的工序排产或ERP的业财一体——定位要守住"数据底座 + 问答/溯源"而非"全流程系统"
2. 一线自建要成立，前提是把建模成本压到"填词典/配schema"而非"画ER图/写集成"，并用自然语言而非SQL做入口——否则滑回低代码孤岛
3. FDE从"厂商派驻的高人力顾问"下沉为"一线业务人 + 轻本体引导工具"的组合，才是对缺IT中小厂可负担的形态（推断）

**给用户的一句结论**：factory-ontology 站在一个真实的社区空白上（确定性 + 轻本体 + 零依赖 + 溯源四合一无同款），技术上经学术背书与实测验证站得住；它能不能成为"中小企业数智化一条思路"，下一步的胜负手不在技术，而在"把它做成 1-2 个强监管行业（阀门/化工/食品溯源）可验收、可计价的可信产品"，用真实案例证明"台账→可问→溯源"这条最轻的路。
