# 需求：模型配置能力增强（可查看/修改/再配置，而非简单切换）

> 用户反馈："模型配置好像也不对，需要增加模型配置的能力，而不是简单的写上，默认的云端 DeepSeek key 和本地模型应该直接配上，但可以修改和再配置。"
> 含义：
> 1. 默认应配置好云端 DeepSeek（含 key）和本地模型（ornith/qwen）——可直接用
> 2. 但用户要能**修改和再配置**：编辑模型参数（名称/类型/base_url/model/api_key）、增删模型、设 active、保存持久化
> 遵循代码极简 + 复用现有 model_config.json。

## 现状
- `codes/config/model_config.json`：已配 3 个模型（local=ornith / cloud=DeepSeek / local_ollama=qwen2.5），active=cloud，api_key 空（从 Hermes .env 读 DEEPSEEK_API_KEY）
- 前端 App.svelte 有模型切换下拉（getModel/setModel 切 active），**无配置编辑**

## 目标文件
- `E:\open-source\factory-ontology-kit\codes\config\model_config.json`（模型配置，默认配好 key/本地模型）
- `E:\open-source\factory-ontology-kit\web\server\ontology.js` / `index.js`（后端模型配置接口）
- `E:\open-source\factory-ontology-kit\web\src\lib\api.js`（前端 API）
- `E:\open-source\factory-ontology-kit\web\src\App.svelte`（前端模型配置 UI）

## 要求
### 1. 默认配置（直接可用）
- cloud DeepSeek：若环境有 DEEPSEEK_API_KEY 则写入 model_config.json 的 cloud.api_key（一次初始化），否则保留空（从 .env 读）
- local 本地模型：ornith:latest / qwen2.5:7b 已配，确保 Ollama 地址正确
- 确保默认 active 可用（cloud 有 key 或 local 可连）

### 2. 模型配置能力（可修改/再配置）
后端：
- `GET /api/ontology/models` → 返回完整模型配置（models 列表 + active + 是否有 key），**不返回明文 api_key 完整值**（脱敏，显示 `sk-***` 或 "已配置/未配置"）
- `POST /api/ontology/models` → 保存完整模型配置（models 数组 + active），支持增删改模型；api_key 若传新值则更新，若留空/脱敏标记则保留原值
- 写回 codes/config/model_config.json（原子写，先写临时文件再替换）
前端：
- 模型管理折叠区/弹窗：列出模型（名称/类型/model/base_url/api_key 状态/active 标记）
- 可编辑每个模型参数（名称/类型下拉/base_url/model/api_key 输入）+ 保存
- 可新增模型、删除模型、设某个为 active
- 保存后调 POST /models，并刷新模型切换下拉
- 保留现有模型切换下拉（快捷切换 active）

## 约束
- 极简：复用现有 model_config.json + getModel/setModel，扩展配置读写
- 安全：api_key 脱敏（不回传完整明文；保存时空值保留原 key）
- 本地优先：默认模型本地可连（ornith/qwen），云端可选
- Svelte 5（$state/$props）
- 不破坏现有问答/建模

## 验收
1. model_config.json 默认配好（cloud 有 key 或注明从 .env 读，local 本地模型就绪）
2. GET /api/ontology/models 返回脱敏配置
3. POST /api/ontology/models 能保存修改（增删改模型 + 设 active + 更新 api_key）
4. 前端能查看/编辑/保存模型配置
5. vite build + pytest 29 passed
