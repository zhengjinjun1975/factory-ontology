# 食品溯源合规说明：对齐与边界

面向中小型食品企业，说明本系统对食品溯源合规要求的支持情况（对齐 + 诚实边界）。

> **原子化与开源合规边界**：本仓库是开源算法原子层（本体认知 / rag / 事件原子），以 Apache-2.0 免费开源、可自部署，不采集/不上传任何用户数据，数据全在工厂本地流转。自动化编排、人在环、反馈学习等属闭源服务，不在本仓库范围内。本节以下溯源能力均由开源侧算法原子提供。

## 〇、开源算法免费与数据不出厂

- **免费可自部署**：本体认知 / rag / 事件等算法原子全部开源（Apache-2.0），企业可自行下载部署，不依赖任何付费闭源服务
- **数据不出厂**：建模、问答、评测、溯源、交付全在工厂本地完成，本系统不向任何第三方（含开发方）上传台账、批次、质检等业务数据
- **被闭源编排调用**：开源原子通过 REST 接口向外暴露，闭源侧只做流程编排（建模流程/人在环/交付打包），算法实现全在开源侧
- **无 SaaS 依赖**：本地 Ollama 可全离线运行，云端 DeepSeek 为可选增强项，不强制联网

## 一、溯源链路（食品安全核心）

食品生产企业须实现"原料 → 生产 → 成品 → 销售"的可追溯。本系统覆盖：

| 环节 | 系统能力 | 对应接口 |
|------|----------|----------|
| 原料台账 | 原料表(供应商/批次/到期日/质检) | `food_raw_materials` |
| 生产批次 | 批次表(产品/数量/日期/班组) | `food_batches` |
| 批次-原料关联 | join 表(正反向追溯) | `food_batch_ingredient` |
| 质检 | 检验记录 | `food_qc` |
| **正向溯源** | 批次 → 产品 + 原料 | `GET /api/trace/forward` |
| **反向溯源** | 原料 → 受影响批次 → 产品（**召回核心**） | `GET /api/trace/reverse` |
| **一物一码** | 溯源码扫码识别批次 | `GET /api/scan?code=` |

**召回场景**：某原料（如 RM008 盐）不合格 → 反向溯源秒级定位受影响批次 → 精确召回。这是食品安全监管的核心诉求，本系统已实现。

## 二、一物一码（每件产品一个溯源码）

- 溯源码格式：`产品编号-批次号`（如 `P003-B005`），扫码即出批次全链路
- 建议落地：在包装印刷二维码，编码 `https://<域名>/?code=P003-B005`，扫码打开 APP 溯源页

## 三、合规支撑能力（T3 已加）

| 能力 | 说明 |
|------|------|
| **审计日志** | 每次 API 请求记录(时间/方法/路径/来源IP/状态码/耗时)，落盘 `output/audit.log`，`GET /api/admin/audit` 可查，满足"操作可追溯" |
| **角色鉴权** | admin(改数据/管理) vs read(查询/溯源)，防未授权改数据 |
| **增量重建** | 数据变更可追踪(数据 hash)，数据来源可控 |
| **数据质量** | `data_quality.py` 校验空值/重复/悬空引用，保证溯源链路完整 |

## 四、诚实边界（不夸大）

- **本系统是溯源信息平台**，不替代企业 ERP/财务/SCM；数据需从台账/ERP 同步（`data_import.py`）
- **非认证机构**：本系统不颁发检测报告、不替代 CMA/CNAS 检测，质检数据须由有资质机构出具
- **标准对齐是建议**：正式商用前应按目标市场标准（GB 14881 生产规范、GB/T 追潮要求、当地食安监管）由企业合规部门审核，本系统提供"一物一码 + 正反向溯源 + 审计"的技术底座
- **数据真实性**：系统如实反映导入的数据；数据的真实性由企业保证

## 五、落地步骤（小型企业）

1. 用 `data_import.py` 把台账(Excel/ERP)同步进知识库
2. 跑 `data_quality.py` 校验数据完整性
3. 设 `FOOD_ADMIN_KEY`/`FOOD_READ_KEY` 控权
4. 包装印溯源码 `产品-批次`
5. 启用审计日志，配合合规审查
