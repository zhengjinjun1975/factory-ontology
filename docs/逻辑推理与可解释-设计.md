# 架构分析 + 需求设计：逻辑推理增强 + 可解释溯源 + 全本地化

**版本**：factory-ontology 目标 v2.8.0
**背景**：社区/文献再评估确认方向（本体驱动 RAG 是主流，KAG 9k★/GraphRAG 35k★/ORT ACL2025），本系统差异化 = 轻量 + 确定性 + 可解释 + 中小厂本地化。本次强化这三点。

---

## 一、现状架构（精炼核心路径）

```
自然语言
  → ontology_qa_v3.answer()      规则引擎(确定性, 覆盖结构化查询, 100%零token)
     命中? 是→返回          否→ 兜底
  → graph_rag.answer_graph()     GraphRAG(子串种子+图遍历+LLM生成)
     命中? 是→返回          否→ miss 引导
```

**瓶颈**：
1. 规则引擎只覆盖结构化模板（数量/极值/过滤/计数），开放式/组合问题直接跳 GraphRAG（LLM 黑盒、有幻觉风险）
2. 答案无可解释性（不显示"命中了什么"）
3. 模型走 cloud(DeepSeek)，数据出厂

---

## 二、需求设计

### A. 逻辑推理桥（LLM → 逻辑查询 → 确定性执行）

**目标**：让更多开放式问题走"零幻觉的确定性路径"，而不是直接掉进 GraphRAG 黑盒。

**架构**：新增 `logical_qa.py`，在规则引擎 miss 后、GraphRAG 前插入：
```
规则引擎 miss
  → logical_qa.nl_to_query(question, D)    LLM 把自然语言转结构化逻辑查询(JSON)
  → logical_qa.execute_query(query, data, D)  确定性执行器(复用规则引擎的字段解析/数值/枚举)
      可执行→返回(确定性)   不可执行→继续
  → graph_rag (LLM 兜底, 保持现状)
```

**逻辑查询 JSON 格式**：
```json
{"intent": "count|extreme|filter|topn|relation|total",
 "attr": "expiry_days", "filter_cn": "乳制品", "rel": "usesRawMaterial", "n": 3}
```

**接口**：`logical_qa.answer(question, data, D)` → (answer, mode="logical") 或 None
**api_server**：ask 流程改为 规则→逻辑→GraphRAG→miss

### B. 答案溯源 / 可解释

**目标**：答案带"命中了什么"证据，对齐"制造业可解释决策"趋势。

**接口**：
- `ontology_qa_v3.answer` 增加返回证据（命中实体/属性/值/规则）
- `api_server /api/ask` 响应加 `evidence` 字段：`{rule, entities:[{name, prop, value}]}`
- APP "智能问答" 面板展示"答为什么"（命中证据 + 规则名）

**可解释性**：规则引擎本就确定（命中 X 实体的 Y 属性 = Z），只需把命中过程暴露出来。

### C. 全本地化（Ollama 离线）

**目标**：完全数据不出厂（中小厂隐私刚需，私有化趋势）。

**接口**：
- `model_config.json` 增 `local_ollama` 模型（base_url=http://localhost:11434/v1）
- `model_llm.py` 支持 OpenAI 兼容的 Ollama 端点
- 文档：`FOOD_MODEL=local_ollama` 即全离线，规则引擎 + 逻辑桥 + GraphRAG 全本地

## 三、Agent 拆解

| Agent | 任务 | 涉及文件 |
|-------|------|----------|
| Agent-A | **逻辑推理桥**：logical_qa.py（nl_to_query + execute_query）+ api_server 集成（规则→逻辑→GraphRAG）+ pytest | 新建 logical_qa.py，改 api_server.py，tests/test_logical.py |
| Agent-B | **答案溯源/可解释**：规则引擎返回证据 + /api/ask 加 evidence + APP 展示 | 改 ontology_qa_v3.py + api_server.py + web/food_app/index.html |
| Agent-C | **全本地化**：model_config 加 Ollama + model_llm 支持 + 文档 | 改 model_config.json + model_llm.py + docs |

**依赖**：A/B/C 相对独立（A 用 data+D；B 改 answer 返回值需与 A 的 execute 兼容；C 独立）。B 的 answer 返回结构变化需 A 同步（统一返回 (answer, evidence)）。
