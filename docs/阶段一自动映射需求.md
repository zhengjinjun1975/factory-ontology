# 需求：阶段一 — 建库自动生成查询映射（data profiling，解决 A/B/C 泛化）

> 依据《综合方案-本体问答泛化.md》：不再硬编码映射，改为建库时 data profiling 自动生成实体总数/极值字段/类型枚举映射，一次性泛化（非逐行业修补）。

## 背景
规则引擎（ontology_qa_v3）的实体总数映射/极值字段/类型计数是硬编码的，导致 9 行业测试漏答：
- A. 实体总数映射硬编码 {设备:equipment,...} → 测线/炮点/项目/船坞/船 计数不命中
- B. 极值字段不全 → 精度/投资/价格/吨位/金额 极值不命中
- C. 类型计数不全 → 大气治理/油轮 类型计数不命中

## 目标文件
- `E:\open-source\factory-ontology-kit\codes\multi_model.py`（_build_lexicon 加自动映射生成）
- `E:\open-source\factory-ontology-kit\codes\ontology_qa_v3.py`（读取词典的自动映射，替代硬编码）

## 要求
### 1. 实体总数映射自动生成（解决 A，multi_model）
- 从 suggest_schema 的表名 + 中文 label 自动生成 {中文实体名: 表名}：
  - 表名：equipment→设备, products→产品, lines→测线, shots→炮点, projects→项目, vessels→船, batches→批次, customers→客户, orders→订单
  - 中文 label（schema 实体 label）直接作为计数词
- 存入词典 `entity_cn2en` 字段
- ontology_qa_v3 实体总数模板改用词典的 entity_cn2en（替代硬编码 {设备:equipment,...}），兜底保留硬编码

### 2. 极值字段自动识别（解决 B，multi_model）
- data profiling：识别数值列（精度/投资/价格/吨位/金额/容量/功率 等 numeric 类型），自动纳入极值模板
- 存入词典 `numeric_fields` 或极值字段表
- ontology_qa_v3 极值模板用该字段表

### 3. 类型枚举自动收集（解决 C，multi_model）
- 枚举列（含产品类型 category/project type/船型 type 等）distinct 值自动进 type_cn2en
- 已部分实现，补全到所有枚举列

### 4. 兜底（ontology_qa_v3）
- 词典有 entity_cn2en/numeric_fields 时优先用，没有则回落硬编码（兼容旧）

## 约束
- 极简
- 不破坏现有命中（阀门/机械/食品 已 100%）
- 泛化：任意新行业自动生成
- 中文正确
