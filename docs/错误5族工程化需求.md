# 需求：错误处理扩为 5 族工程化（SoGuru 分类法 + 退避重试 + 语义校验 + guardrail）

> 依据调研《工厂本体检索优化调研-2026.md》：错误处理从"4 类 formatError"升级为"5 族错误分类 + 429退避重试 + 输出语义校验 + 输入 guardrail（fail-open）"（SoGuru 2025 工程指南）。

## 背景
当前 formatError 分 4 类（网络/模型/数据/后端），缺：限流(429)/配额、语义/幻觉校验、输入策略(离题/注入/PII)、重试退避预算。

## 目标文件
- `E:\open-source\factory-ontology-kit\web\src\App.svelte`（前端 formatError 扩展）
- `E:\open-source\factory-ontology-kit\web\src\lib\api.js`（fetch 封装，重试/退避）

## 要求
### 1. formatError 扩为 5 族（App.svelte）
分类并显示：
- **基础设施**（超时/5xx/网络分区）→ "服务异常，请重试"
- **限流**（429 配额超限）→ "请求过于频繁，请稍后再试"（提示退避）
- **语义**（幻觉/schema不匹配/拒答）→ "模型输出异常" 
- **输入策略**（不安全内容/注入/PII）→ "输入不被允许"
- **未知** → 显示原始错误
判定：看 res.error / HTTP 状态码（429→限流，5xx→基础设施）

### 2. fetch 重试 + 退避（api.js）
- fetch 封装：429/5xx 自动重试（指数退避 + 抖动，上限 3 次）
- 预算：总重试不超过 N 次

### 3. 输出语义校验（可选，极简）
- LLM 兜底回答若是空/纯噪声 → 标记为语义错误

### 4. 输入 guardrail（可选，极简）
- 前端问题输入做基本校验（长度上限、禁止明显注入模式）

## 约束
- 极简，只改必要处
- 不破坏现有功能（问答/建模/看板）
- fail-open：校验/分类失败时不阻塞正常流程

## 验收
1. formatError 分 5 族（含 429 限流提示）
2. api.js fetch 有重试退避（429/5xx 重试）
3. 现有功能不破坏（问答/建模）
4. vite build + pytest 29 passed
