# 需求：查询改写（CoTKR 思路，复杂查询规则未命中时改写再检索）

> 依据调研《工厂本体检索优化调研-2026.md》：复杂查询加"查询改写/知识改写"（CoTKR），在规则未命中时先改写查询再检索，性价比最高。解决"保质期最长的产品"等复杂/口语化查询。

## 背景
当前查询链路：规则引擎(确定性) → GraphRAG(BFS子图+LLM) → BM25 → miss。复杂/多跳/口语化查询规则未命中后走 GraphRAG，但可能子图检索不准。

## 目标文件
- `E:\open-source\factory-ontology-kit\codes\graph_rag.py`（answer_graph 加查询改写）

## 要求
1. 在 answer_graph（GraphRAG 兜底）**开头加"查询改写"**（CoTKR 思路，用 LLM）：
   - 当规则引擎未命中（开放式/复杂查询），先让 LLM 把问题改写/标准化为更适合检索的形式（提取关键实体/属性词）
   - 例："保质期最长的产品" → 改写为"产品 保质期 最大 极值"（提取实体+属性+意图）
   - 用改写后的问题做 find_seeds 检索，提高种子/子图命中
2. **LLM 失败回落**：改写失败则用原问题（不阻塞）
3. 复用 model_llm.llm_generate
4. 极简：只加改写步骤，不改子图提取/LLM生成逻辑

## 约束
- 极简，复用 model_llm
- LLM 失败回落（不阻塞）
- 不破坏现有命中（有多少台设备等规则查询不受影响，改写只在 GraphRAG 兜底触发）
- 中文正确，泛化

## 验收
1. 复杂查询（如"保质期最长的产品"）走 GraphRAG 时先改写再检索
2. 改写失败回落原问题（不崩）
3. 现有规则查询（有多少台设备/客户总数）不破坏
4. pytest 29 passed
