# 需求：前端默认示例数据 + 数据看板空状态加固

> 基于用户反馈："数据文件输入需要默认例子数据目录并默认选择；数据看板的加固，在没输入之前应该不是报错。"
> 遵循代码极简原则，不重写整个组件。

## 目标文件
- `E:\open-source\factory-ontology-kit\web\src\App.svelte`（主组件，文件输入）
- `E:\open-source\factory-ontology-kit\web\src\components\DashboardPanel.svelte`（数据看板）
- `E:\open-source\factory-ontology-kit\web\server\ontology.js`（后端桥接，示例数据/统计）
- `E:\open-source\factory-ontology-kit\web\server\index.js`（后端路由）
- `E:\open-source\factory-ontology-kit\web\src\lib\api.js`（API 层）

## 优化1：默认示例数据目录 + 默认选择

现状：文件输入框空，显示"选择 CSV/JSON 文件…"，用户需手动选文件。后端 statsOntology 硬编码 `data/equipment.csv`（可能不符/空→报错）。

要求：
1. **后端提供示例数据接口**：`GET /api/ontology/examples` 返回预置示例数据文件列表（如 `data_valve` 目录下的 valve_products.csv 等、`data/ai4i.csv`），供前端展示可选示例
2. **前端默认选择示例**：文件输入区加"示例数据"下拉/列表，默认选中第一个示例（如 data_valve 的 valve_products.csv），点击即可加载该示例（读取后端示例文件内容 → 走现有 setupOntology 建模）
3. **极简**：复用现有 setupOntology 流程（把示例文件内容读给前端，前端走上传建模）；不加新框架

## 优化2：数据看板未输入前空状态加固

现状：未建模/无数据时，DashboardPanel 调 fetchStats 返回 error，显示"统计加载失败"或"网络错误"——这是"没输入之前就报错"。

要求：
1. **后端区分空状态**：statsOntology 在数据目录无有效数据（未建模）时，返回 `{ ok: true, stats: null, empty: true }`（而非 error），或 `{ ok: false, empty: true, error: '尚未建模' }`
2. **前端友好空状态**：DashboardPanel 当 `empty` 时显示友好提示（"尚未建模，请先在数据建模页上传数据"），而非红色报错；仅真网络错误（后端不可达）才显示"网络错误"+重试
3. **看板空态不报错**：未建模时不展示故障/告警横幅、不展示 KPI（因为无数据），只展示空状态引导

## 铁律
1. **极简**：只改必要处，不重写组件，不加第三方库
2. **Svelte 5 语法**：$props()/$state()，不用 export let
3. **不破坏现有功能**：上传建模/问答/分析/看板（有数据时）正常
4. **浅色工业风**：空状态用中性灰提示（非红色报错）

## 验收
1. 文件输入区显示默认示例数据（默认选中第一个示例）
2. 点示例可加载并建模
3. 未建模时看板显示"尚未建模"空状态（非报错）
4. 有数据时看板正常显示（含诊断式告警）
5. `node node_modules/vite/bin/vite.js build` 无 error
