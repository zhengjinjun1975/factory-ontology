### 接入点（`_principal` 追加片段）

```python
    # ── 第4轮(2026-09-24): SSO / OIDC 可选适配器 ──
    #   本地静态 key / 租户 key / 本地令牌(上面) 永远优先, SSO 只作附加入口。
    #   默认未配置 → _sso() 为空 registry, authenticate 恒 None → 行为逐字段不变。
    try:
        _sr = _sso()
        if _sr is not None:
            _sp = _sr.authenticate(key)
            if _sp is not None:
                return _sp
    except Exception as e:
        logger.warning("SSO 校验异常(拒绝该凭据, 不影响本地凭据): %s", e)
    return None
```

## 3. 声明映射规则

| 项 | 规则 | 缺省行为 |
|---|---|---|
| 角色声明 | `role_claim`（支持点号路径，如 `realm_access.roles`；可为字符串或数组）→ 经 `role_map` 映射到 `admin`/`read` | 无 `role_map` 时只认字面 `admin`/`read` |
| **角色缺省/映射不到** | **一律拒绝（401）** | **绝不默认 admin、也不默认 read** |
| 多角色 | 数组中任一映射为 `admin` → `admin`；否则若任一为 `read` → `read` | — |
| 租户声明 | `tenant_claim`（默认 `tenant`）取值 → 交给**第 1 轮 `tenant.resolve`** 校验存在性 | `require_tenant:true` 时缺失 → 401；声明存在但**不在注册表** → 403 |
| 签名 | `HS256`（共享密钥）或 `RS256`（公钥）；`alg` 与配置不符（含 `none`）→ 拒绝 | — |
| 时间 | `exp` 必填；`exp` 缺失 → 拒绝；`nbf` 存在则校验；`leeway` 容忍 | 过期 / 未生效 → 401 |
| issuer / audience | 配置非空则**必须匹配**（aud 支持 str/list，取交集） | 配置为空则跳过该校验 |
| 主体 | `sub`（回退 `preferred_username` / provider 名）→ `subject = sso:<sub>`；`auth = "sso"` | — |

映射结果注入既有租户/审计链：`_establish_tenant()` 用 SSO 令牌的 `tenant` 声明解析租户上下文，审计事件带 `auth="sso"`、`tenant=<tid>`。

## 5. 没做到 / 不确定项（诚实清单）

1. **LDAP 未实现、未实测（接口占位）**。标准库无 LDAP 客户端，本轮**不引第三方依赖**（离线私有化底线），故 `LDAPProvider.authenticate()` 恒返回「未实现」并被拒（fail-closed，绝不静默放行）；`/api/auth/sso/status` 显式标注 `implemented:false`。**接入方式说明（后续落地时）**：需引入 LDAP 客户端（如 `python-ldap`/`ldap3`，均为第三方）或走「LDAP → IdP → OIDC」间接路径（推荐：让企业 IdP 做 LDAP 联邦，本系统只对接 OIDC，从而**保持零依赖**）。真正落地需实测：bind 认证、用户过滤器、组→角色映射、TLS(`ldaps://`)、连接池与超时。

2. **RS256/HS256 取舍理由**。
   - **HS256（共享密钥）**：零依赖、无密钥解析，适合「同一信任域内的单 IdP」或自签场景；缺点是密钥须在验签方本地持有，**多实例共享同一密钥 → 轮换时要同步**，且密钥泄露即全量可伪造。**本轮把它作为「可完全离线自测」的默认落地算法并全量实测。**
   - **RS256（公钥验签）**：验签方只持公钥，**私钥不外发**，适合「IdP 与资源服务分属不同信任域」的生产部署；用纯标准库实现了 PKCS#1 v1.5 + SHA-256 + 最小 DER 解析（**真实验证通过，见 4.1 第 8 节**）。限制：只认 `RS256`；未实现 `ES256`/`PS256`/`RS384/512`；**公钥需本地内置**（PEM），**不做网络 JWKS 抓取**（离线纪律）——生产若用 JWKS 轮换，需另行设计「离线/带外同步公钥」的机制。
   - 两者都**不联网**：密钥/公钥来自本地配置或环境变量。

3. **多进程 / 多 worker 注意点**。`sso.py` 是**无状态**的纯函数式校验（不做缓存、不落盘），因此多进程/多 worker **天然共享同一份配置**、无状态一致性问题；但：①配置在**进程启动时/首次 `_sso()` 时读取并缓存**（`api_server._SSO` 惰性单例），**改配置需重启各 worker**（或后续加 SIGHUP/热重载）；②SSO 失败的判定**不走第 3 轮失败计数**（`_principal` 返回 `denied_reason` 属「已识别但被拒」→ `count=False`），因此**SSO 凭据不参与防爆破封禁**（JWT 高熵、签名爆破不可行的取舍；如需可另接 IP 维度限速）；③HS256 共享密钥在多实例间必须一致。

4. **密钥轮换注意点**。HS256 轮换需**双密钥并行窗口**：当前实现每个 provider 只持**一个** `secret`/`public_key_pem`，轮换瞬间旧令牌会全部失效。生产建议：配置**两个 provider（新旧密钥各一，同 issuer/audience，都 enabled）**，让注册表顺序尝试、命中任一即通过，观察期结束后停用旧 provider。RS256 同理（旧/新公钥各一个 provider）。**未实测该双 provider 轮换流程**（本轮只验证了「多 provider 顺序尝试」的机制，见 4.1 第 8 节末条）。

5. **`audience` 语义**：本实现为「令牌 aud 与配置 aud 取**交集非空**即通过」（支持多资源标识）。若企业要求「aud 必须精确等于单一值」，需收紧（当前可用单元素 aud 数组近似，但非严格相等语义）。

6. **未做签名算法混淆攻击的穷举测试**：已拒绝 `alg:none`、拒绝 alg 与配置不符、拒绝 HS256 令牌被 RS256 provider 误判（见 4.1 第 8 节末条），但**未**系统化测试所有跨算法混淆组合（如 RS256 公钥当 HMAC 密钥的经典混淆攻击）——本设计中每个 provider 固定 `alg`，混淆在结构上不会命中，尚未单独取证。

7. **`scripts/eval_qa_baseline.json` 被本次「跑全门」重写**（`hit_rate` 0.568→0.628、`fabricate` 4→0 等），这是 `run_all_gates.py` 慢门 `eval_qa.py` 的**正常落盘行为**（基线门自身 PASS），**非本轮 SSO 改动所致**；是否随明早提交一起纳入请由你定夺。

8. **未做真实 IdP 对接实测**：本轮所有令牌均由自检脚本用本地生成的示例密钥/测试密钥签发，**未连任何真实 IdP**（离线纪律）。
