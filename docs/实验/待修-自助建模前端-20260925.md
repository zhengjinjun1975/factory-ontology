## A. 状态混乱（最要紧）

- A1 **建库后未自动激活**（实测）：自助建模成功，但问答仍答"阀门制造"。
  根因（已核）：激活态存在 BFF **会话内存**里（`setCurrentKb`），服务一重启就回落默认；
  而库本体文件与 `kbs.json` 注册是**持久**的 → 三处状态不一致。
- A2 **合规面板算的不是当前库**：`/api/standard/compliance` 写死读全局
  `codes/config/ontology_schema.json`，与当前激活 KB 无关。
- A3 **标准导出物（ttl/jsonld）同样按全局那份导**，与当前 KB 无关。
- A4 **同一数据目录被两个 KB 占用**没有阻挡（未实测，按代码判断缺校验 → 标「未核」）。

## B. 界面上你提的

- B1 候选数据目录改**下拉一行**（默认收起、点开展开），不要常驻窗口平铺。
- B2 **浏览按钮用站内既有按钮样式**，不许自造视觉；选择器内部用常规控件形态。
- B3 自动匹配：kb 名 ↔ 数据目录**双向推导**，候选**从真实枚举**得出，**默认不写死**。
- B4 顶部常显「当前本体：某某库」，切库时明确提示"生效本体已变"。

## C. 起服务与错误文案

- C1 **BFF 未代理 `/api/standard/`** → 合规面板拿不到 JSON（拿到首页 HTML）→ 显示空。
- C2 **错误文案骗人**：未登录/会话过期 401 被显示成"后端建模失败"。
- C3 **登录态应落盘**，重启服务不该把人踢出去（现在一重启就要重登）。
- C4 **服务 key 应落配置文件**（BFF 已有 `readApiKeyConfig()`），不能只靠环境变量；
  现在起服务漏带 key 就全线 401。

## D. 建模质量（用户 2026-09-25 实测暴露）

- D1 **自动建模产出"实体平铺"本体**：合规面板实测 `类层次 0`、核心描述项 83%<90%、
  提示「无 subClassOf：实体平铺，国标 §5.3 要求派生层次」。
  → 建模时应**自动派生类层次**（按业务域/字段把实体归到上层类）+ **补实体 Definition**，
  使产出的本体天然达标；Definition 由模型**建议**、**人来确认**（守住"模型只建议"红线）。
- D2 门的期望值不许写死数量：`verify_kb_registry` 曾断言 33 个 KB，用户新建库后变 34 → 门
  报红。改为**按注册表真实内容校验**，不依赖"数据刚好有 N 个"。
