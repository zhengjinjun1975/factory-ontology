## 2. 改动清单

### 2.1 `codes/ontology_qa_v3.py`
1. **修已知缺陷①（数值比较问法被"实体总数"劫持）** — 实体总数分支加守卫：问句含
   `大于/小于/高于/低于/超过/少于/以上/以下` 或区间（`到`/`之间`）时**不返回实体总数**，
   落到下方 range 分支按属性阈值过滤计数。
   `机器中工艺温度大于310.01的机器有多少`：`有 10000 个机器`（误答）→ `工艺温度大于310.01的(5037):`
   （命中）；横向修好 food/valve/auto_parts/ai4i/chem 等一大类区间问法。
2. **修已知缺陷②（"页数最大"答成"最大库存"= 编造）** — `_extreme_field()` 加**反向守卫**：
   泛化极值推断只在"最"前的中文词尾部能对上已知属性/数值字段名时才生效，否则不猜。
   `图书中页数最大是多少`：`最大库存的记录…`（编造）→ `暂不支持该问题`（如实拒答）。
3. **收紧"值过滤计数"兜底**（`_value_filter_count` 调用点）：① 极值问句（含"最X"）不再落到
   该兜底（挡掉 `设备中纯度最大是多少`→`符合条件共 2 条` 这类与问题无关的编造计数）；
   ② **仅**"裸实体计数"形态（`有多少个X`/`X总数`）且跨域时才不落到该兜底
   （挡掉 `有多少个催化剂`→`符合条件共 1 条` 编造）；**不**拦 `法兰的数量` 这类正常取值过滤。
4. `_value_filter_count(q, data, with_names=False)`：新增 `with_names` 返回命中实体名，
   供 `evidence.build_trace` 产出可回溯证据（老调用点仍拿 2 元组，不改行为）。
5. **新增统一信封**：`_MISS_MARKERS`、`_BARE_COUNT_RE`、`_miss_reason()`、`answer_envelope()`。
   - `answer_envelope()` 包住 `answer()`，产出 `{answer, hit, reason, evidence[], advisory?, raw_answer, source}`；
   - 引擎异常**不静默吞**：写入 `reason`/`answer` 原文；
   - **不改** `answer()`（老字符串返回与老字段一律不动 → 向后兼容）。

## 4. 没做到 / 不确定项（如实写，不假报）

1. **未接线到 `api_server.py`（受文件隔离限制）。** 批 2 的 `hit/reason/advisory/evidence_trace`
   目前只在 `ontology_qa_v3.answer_envelope()` 与 `ask_service.envelope_from_result()` 可用；
   线上 `/api/ask` 返回**尚未**带上这些新字段。接线是主链路出口一行：
   `result = ask_service.envelope_from_result(result, 知识库名)`，留待主控/批 3 统一接。
   因此"所有分支都带 hit"这一条，在**核心/服务层**已满足并被 `verify_qa_envelope.py` 验证，
   但**HTTP 响应层**要到接线后才生效。
2. **实体计数类误答未修（词典数据问题，非本批允许文件）。** `entity_cn2en` 在多个 KB 里是
   模板残留/缺失（如 energy_station 为 `null`、chem 把「产品」映到 `mach_products` 而实际表名
   是 `Chem_products_*`），导致 `有多少台设备`/`设备总数` 仍答成 `有 0 台设备`。
   **这类仍计入命中（hit=true）且带证据，没有被信封"掩盖成未命中"**——按要求"不许把错答
   掩盖成未命中"。修它需改 `codes/config/lexicon_*.json`（不在本批允许范围，且会动批 1 量尺）。
3. **`_extreme_field` 反向守卫的副作用（trade-off）。** library「借阅量最大」（数据里确有
   `borrowed` 字段，但词典键名是 `borrowed` 而非「借阅量」）由"答成最大库存（误答）"改为
   **如实拒答（未命中）**；即由"误答"变"未命中"，命中率不变、误答率下降。这属词典缺中文名，
   根因同上。同类：`设备中功率平均是多少`（KB 数据无功率字段）仍答 `符合条件共 N 条`（误答未修）。
4. **"空答" 41 条未变。** eval 的 `empty_zero`（无答案类回"有 0 台X"）在批 2 的**信封层**已被
   `_miss_reason` 的"裸实体计数且计数为 0"规则判为 `hit=false`（信封内如实未命中），但
   `eval_qa.py` 自己的 `empty_zero` 口径不变仍是 41（量尺口径不动，符合"不动批 1 量尺"）。
   两者口径差异已在报告中说明，不冲突。
5. **跨域判定依赖词典词表，存在残余不确定性。** `is_cross_domain_data_query` 以"问句是否含本 KB
   任何领域词"判跨域；KB 词典缺词时，域内问句可能被误判为跨域。为此批 2 把该判定**只**用在
   "裸实体计数"形态上（不拦 `法兰的数量` 这类取值过滤），把误伤面压到最小；但仍不能保证 100% 精确。
6. **证据截断到 50 条**（`TRACE_MAX`）。万行级 KB 的计数/区间类问题，信封里只回前 50 条记录证据
   （`hit` 判定不受影响）；如需全量需另接分页/摘要证据。
7. **`advisory` 恒为 `None`**（批 3 模型建议层占位，本批不启用模型）。
