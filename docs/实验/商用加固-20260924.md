### 1.2 加固内容（只加不松）

1. **静态 key 可选过期**：`FOOD_ADMIN_KEY_EXPIRES` / `FOOD_READ_KEY_EXPIRES`（ISO8601 或 epoch 秒）。配置了且已过 → 拒绝（`denied_reason="…key 已过期"`）。不配置 = 行为与改前**逐字节一致**（永不过期）。
2. **可签发短期令牌（真过期）**：配置 `FOOD_TOKEN_SECRET` 后
   - `POST /api/auth/token`（**需 admin 凭据**）签发 `fotk1.<role>.<exp>.<sig>`，`sig = HMAC-SHA256(secret, "fotk1.<role>.<exp>")[:32]`；`ttl_seconds` 限制 `1..7776000`（≤90 天）。
   - 校验用 `hmac.compare_digest`（常量时间），校验签名 + `exp`；过期 → 401。
   - 未配 `FOOD_TOKEN_SECRET` → 任何 `fotk1.*` 令牌验签失败（fail-closed），且签发接口 503。
   - 凭据可取 `X-API-Key` 或 `Authorization: Bearer <token>`（`_extract_key`，X-API-Key 优先）。
3. **结构化鉴权审计**（主体/时间/动作/结果）：`login` 事件新增 `subject`（`static-admin`/`static-read`/`token-<role>`/`anonymous`）、`action`（`authenticate`/`issue_token`/`whoami`）、`result`（`grant`/`deny`）、`auth`（`static`/`token`）；`ts` 原有。**deny / issue_token 额外写入哈希链账本**（`AuditChain.record_access`，防事后删改）；成功请求不写链（避免热路径 IO）。
4. **留存 ≥6 个月**：新增 `FOOD_AUDIT_RETENTION_DAYS`（默认 **200 天 ≈ 6.5 个月**）。`_prune_audit_archives()` 只删超过留存期的轮转归档，主日志永不删。哈希链账本**不可删行**（删行会被 `verify_chain` 抓 gap），留存策略为「全量保留 + `export_audit` 归档」，新增 `retention()` 返回最早/最新 ts。
5. 审计文件路径新增 `FOOD_AUDIT_FILE` 覆盖（默认路径不变），用于测试隔离。
6. **未知凭据 → `None`（拒绝）**，无任何全局登录态；`/api/auth/whoami` 逐请求从当前请求头重新校验（**不读全局**——规避「共享全局鉴权态」静默绕过那一类 P0）。

## 4. 自检发现的真实缺陷（本轮已修）

**审计哈希链并发写会断链（P1，真实复现）**。首次跑 `verify_hardening.py` 时该门**红**：

```
  FAIL 并发写后哈希链完整(PASS) | bad=[(5,'chain_break','prev_checksum 与上一条不衔接(链被改动)'), (12,'chain_break',...)]
```

根因：`_append()` 用**两个连接**——先 `_last_row()` 读上一条 checksum，再另开连接 INSERT。并发下两个写者读到同一个 prev → 链断裂。修复：单连接 + `BEGIN IMMEDIATE` 把「读 prev + 插入」放同一事务，并显式 `busy_timeout`。修后同一门转绿（§3.3），且 `tests/test_audit_chain.py` 仍 `ALL PASS`。
