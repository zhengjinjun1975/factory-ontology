## 3. 设计与实现

### 3.1 令牌格式（附加，不破坏老令牌）

| 格式 | 段数 | 用途 | 是否可吊销 |
|---|---|---|---|
| `fotk1.<role>.<exp>.<sig>` | 4 | 老格式（无租户） | 否（无 jti） |
| `fotk2.<role>.<tenant>.<exp>.<sig>` | 5 | 多租户（第 1 轮） | 否（无 jti） |
| `fotk3.<role>.<tenant\|->.<exp>.<jti>.<sig>` | 6 | **本轮：可吊销访问令牌** | 是（按 jti） |
| `fotkr1.<role>.<tenant\|->.<exp>.<jti>.<sig>` | 6 | **本轮：刷新令牌** | 是（按 jti） |

- `tenant` 为空用占位符 `-` 对齐段数，避免歧义。
- 签名：`HMAC-SHA256(secret, "<prefix>.<role>.<tenant|->.<exp>.<jti>")[:32]`，校验用 `hmac.compare_digest`（常量时间）。
- **默认关**：`POST /api/auth/token` 不传 `revocable/with_refresh` 时，输出仍是 `fotk1/fotk2`（兼容底线，`verify_hardening.py` 的「fotk1 四段」断言与 `verify_tenant.py` 的「fotk1/fotk2」断言均仍绿）。

### 3.2 吊销

- 端点：`POST /api/auth/revoke`（需 admin）`{jti? , subject?, reason?}`，二选一。
- 立即失效：`_principal` 对带 jti 的令牌查 `token_guard.is_revoked(jti)` → 真则 `denied_reason="令牌已被吊销"` → **401**（下一请求即生效，无需重启/黑名单重载）。
- 有界 + 清理：所有可吊销令牌登记在 `tokens` 表；`prune()` 按 `exp`（+60s 宽限）删除过期行，再按单表硬上限 `FOOD_AUTH_STATE_MAX_ROWS`(默认 50000) 兜底删最旧。**不存在无界增长**。

### 3.3 刷新轮替

- 端点：`POST /api/auth/refresh` `{refresh_token}`（刷新令牌即凭据，无需再带 key）。
- 轮替：每次刷新 → **新访问令牌 + 新刷新令牌**；被换下的旧刷新令牌 `consumed=1`（用后即废）。
- 复用检测：`consume_refresh` 原子判断是否首次消费；非首次 → 审计 `action=refresh_reuse, result=deny` 并 **401**。
- 刷新令牌**不能**当访问凭据用（`_principal` 直接拒）。

### 3.4 限速 / 防爆破

- 计数键**两路**：`subj:<主体>` 与 `ip:<来源 IP>`（`request.client.host`）。
- 触发：滑窗内任一键失败累计 ≥ 阈值 → 对命中的键施加短时封禁；封禁期内该键的**无法识别凭据**请求 → **429**（带 `Retry-After`）。
- 审计：`ban`（封禁）、`throttle`（封禁期内命中）、`unban`（到期自动解除 / 手动解除）全部落 JSONL 审计 + 哈希链账本。
- 可配：`FOOD_AUTH_FAIL_THRESHOLD` / `FOOD_AUTH_FAIL_WINDOW` / `FOOD_AUTH_BAN_SECONDS`。

**关键防误伤设计（这是本轮的硬门，也是初版被自检抓红的点）**：只有**无法识别的凭据**（签名错/未知 key，`_principal` 返回 None）才计入失败计数；**已识别但被拒**的（令牌已吊销/已过期、刷新令牌误用、角色不足）**不计数**（`count=False`）。否则正常客户端在轮替间隙用旧令牌会被自己的失败计数误封。此外**鉴权成功即清空该主体与来源的失败计数**。

### 3.5 运行时状态目录（有界）

- 默认 `FOOD_AUTH_STATE_DIR = <repo>/var/auth_state`（**不在**任何 KB 数据目录 `codes/data*` 下；已加 `.gitignore`）。
- 单库 `auth_state.db`（SQLite，WAL + busy_timeout），三张表：`tokens`（含 revoked/consumed 标志）、`auth_fail`、`bans`，全部按时间/序号清理 + 硬上限。
- 实测：真实负载下 `db_bytes≈45KB`；硬上限测试（`max_rows=200`，灌 1000+1000）→ `tokens_rows=200, fail_rows=200, db_bytes=204800`。

## 4. 阈值与窗口取值依据

| 参数 | 默认 | 依据 |
|---|---|---|
| `FOOD_AUTH_FAIL_THRESHOLD` | **10 次** | 业界防爆破常见区间为「5–10 次后锁定」（OWASP ASVS 2.2.1 / NIST SP 800-63B 均要求对连续失败做节流/锁定）。取 10 以在「挡暴力枚举」与「容忍合法用户几次手滑/配错 key」之间平衡；过小（如 3）易误封，过大削弱防护。 |
| `FOOD_AUTH_FAIL_WINDOW` | **300s** | 与常见限速窗口一致（5 分钟滑窗）；短窗使偶发波动不长期累积，长窗利于识别慢速爆破。 |
| `FOOD_AUTH_BAN_SECONDS` | **300s** | 任务要求「短时封禁」；5 分钟足以打断自动化爆破节奏，又不至于长时间拒绝一个健忘的正常用户。 |
| `FOOD_AUTH_STATE_MAX_ROWS` | **50000** | 状态库单表硬上限兜底（约数 MB 量级），保证任何异常场景下文件体积有界。 |

> 所有阈值**均可配**；自检用 `3 / 60s / 5s` 的小值以便快速观察封禁与到期解除（同时证明"可配"生效）。

### 5.3 抓到的真 bug（自检价值）

初版把「已吊销/已过期令牌、刷新令牌误用、角色不足」也计入了防爆破失败计数，导致**批内后段请求被 IP 级联封**：自检当场抓到 `批量吊销后两张令牌均 401 | t1=401 t2=429`、`刷新令牌当访问凭据用 → 401 | status=429`、`前若干次失败 = 401 | codes=[429,429,...]`。定位为「已识别但被拒 ≠ 猜口令」，改为**仅对无法识别的凭据计数**后全部转绿。这条正是「验真不靠声明」的价值。

## 7. 没做到 / 不确定项

1. **无状态老令牌（`fotk1`/`fotk2`，无 jti）无法按 jti 吊销**。这是格式所限：没有唯一标识就无从精准吊销。默认路径签发的仍是老格式（为兼容），因此**默认签发的令牌不可吊销**——需要可吊销能力时，调用方必须显式传 `revocable=true`（或在后续轮次把端点默认改为可吊销，属破坏性变更，本轮未做）。
   - 备用手段（未实现，仅设计建议）：对老令牌可按"主体 + 签发时间窗"整体吊销，但当前老格式不含签发主体/时间，故不可行。
2. **吊销的生效范围限于本机共享同一 `FOOD_AUTH_STATE_DIR` 的进程**。同一 SQLite 文件 + WAL + busy_timeout，可支撑**单机多进程/多 uvicorn worker**；**跨机 / 多容器部署下各副本的吊销名单互不可见**（未接 Redis/DB 共享）——需把状态目录放到共享存储或改造为集中式存储。本轮未做跨机一致性验证。
3. **吊销名单延迟**：吊销是"下一请求查表即失效"，无推送；已建立长连接/本地缓存的客户端不受影响（本项目无该形态）。
4. **限速是内存外落盘（SQLite）计数，非分布式限速**。多副本部署时各副本各自计数（同样受第 2 点限制）。
5. **IP 维度在 NAT/共享出口下可能误伤**：已用「正常凭据请求绕过封禁 + 成功即清零」缓解，但若攻击者与被误伤用户在同一出口 IP 且后者也用**无效**凭据，仍可能被 429——属已知权衡，未做更细粒度（如设备指纹）区分。
6. **`ban_seconds` 自动解除的审计是"惰性"触发**：只有在封禁到期后有请求命中该键时才写 `unban` 审计（`is_banned(just_expired)`）；若长时间无访问，则到期那一刻不会有即时审计，直到下一次命中。未做后台定时清理任务。
7. **未验证高并发下 `auth_state.db` 的写竞争**（WAL + busy_timeout 已配，但未做多 worker 压测）；`verify_token_guard.py` 的并发段是只读业务端点，未压测并发写状态库。
8. **`.gitignore` 追加 `var/` 超出任务列举的允许文件范围**（仅一行，用于避免运行态被提交），如需严格限定请移除。
9. 运行 `run_all_gates.py` 的评测门会**重写 `scripts/eval_qa_baseline.json`**（该差异源自第 1/2 轮未提交改动，与本轮鉴权无关）；为保持本轮 diff 干净，已将该文件**还原到 HEAD**。
