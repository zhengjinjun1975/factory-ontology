### 注册表设计（以代码为准）
- 单一真相源 = `codes/config/kbs.json`（现有 **33** 个 KB）。问答引擎 `api_server._load_kbs()` 的读法就是 `json.load(KBS_FILE).get("kbs")`（`api_server.py:83-90`）。新 KB 只写这份 JSON 即被引擎感知，**零改引擎、零重启**。
- 路径口径与引擎一致：`data_dir`/`nt` 相对 `codes/`（`_resolve_data_dir`/`_resolve_nt`），`lexicon` 相对 `config/`（兼容个别写成 `config/lexicon_x.json` 的条目）。
- 字段映射：`data_dir`→数据目录绝对路径；`词典层`→`dict_layer`（`{public:{read_only:true,...}, factory:{read_only:false,...}}`）；`数据是否就绪`→`data_ready`（bool，真实探测）。

### 词典分层语义（重要，诚实说明）
- **公共工业本体层**（只读）：`codes/industrial_dict/*.json`（`00_basis` + 行业层 `01_valve_pump`/`02_fine_chem`/`03_geophysics`），跨行业稳定骨架，开源算法资产。
- **工厂专属层**（可写）：`codes/config/lexicon_<kb>.json`，企业私有词，按 KB 隔离。
- 两层合并的**既有**规则是 `kb_wins`（工厂层覆盖公共层，见 `industrial_dict_loader` 原文档）。本任务**未改引擎默认行为**，而是：
  1. `merge_dict_layers(on_conflict="error")` 可把「同词不同规范名」升级为**报错** `DictLayerConflictError`（不静默覆盖）；
  2. `dict_layer_report(kb)` / `detect_layer_conflicts(kb)` 把「工厂层覆盖公共层」的**不一致项显式暴露**（默认合并下这些项本是静默的）；
  3. `dict_asset` 守卫拒绝把工厂词典写进只读公共层。
  > 即：**默认仍向后兼容（kb_wins）**；「报错不静默覆盖」是提供**可选严格模式 + 可见化报告**，不是把默认改成报错。见 §4「未做到/不确定」。

## 4. 哪些没做到 / 不确定（诚实清单）

1. **`kb_registry.py` 尚未成为引擎的必经路径**：依约「不改引擎」，故引擎仍直接读 `kbs.json`（`api_server._load_kbs`）。`kb_registry` 目前是**统一入口 + 自检 + 运维/未来接入点**，引擎并未 `import` 它。要做到「引擎统一走注册表」，需引擎侧改动（本任务红线，未做）。
2. **「冲突报错不静默覆盖」默认未开启**：默认合并仍是 `kb_wins`（向后兼容，`merge_industrial_dict` 原行为逐字节不变）。「报错」只在 `on_conflict="error"` 时生效；「不静默」靠 `dict_layer_report` 可见化。**未把默认改成报错**——否则会改变引擎现有问答行为（红线）。
3. **真实 KB 的分层不一致面很大**：`valve` 工厂层与公共层有 **23 处**不一致（`entity_cn2en` 8、`type_cn2en` 6、`status_cn2en` 6、`synonym_map` 3）。这些多为**设计内覆盖**（工厂层用表名 `valve_equipment` 覆盖公共通用名 `equipment`），非数据错误；但说明「工厂词典 `_public_dict_merged=true`」后公共层仍在演进，二者已漂移。**未做对齐修复**（涉及数据，红线）。若将来强制严格模式，需先批量确认这 23 类覆盖。
4. **`huaneng` 脱敏未做**：用户已定「远端发布前脱敏」，本次仅登记不执行（未改数据）。
5. **`e2ecust`/`valve2`/`valve3`/`valve9`/`factory_multi_*` 共享 `data_dir="data"`** → 探测对它们均报 `ready`（因 `codes/data` 确有文件），**这会掩盖「本 KB 无独立数据」**。已在报告标注；更精确的归属判定需要 KB↔数据目录一一对应（涉及数据变更，未做）。
