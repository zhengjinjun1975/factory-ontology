## 四、为什么只能到 77%（上限分析，不粉饰）

`ent_rate = Σ(实体命中项数) / (实体数 × 8)`。具名子类以「类实体」形式落在 `entities` 里，于是：

```
ent_rate = (6N + k + 6S) / (8(N+S))
  N = 原实体数, k = 获得具名子类的父实体数, S = 新增子类实体数
```
- 每加一个子类实体只补 1 项（父实体的 HasSubclass），而分母同时 +8 —— **子类越多，比率越趋近 6/8 = 75%**，只能略高于 75%。要抬高必须让**更多实体获得子类**且**子类数尽量少**。
- valve 只有 6/8 个实体带真实分类列（`Valve_sales`、`Valve_batch_ingredient` 只有外键/度量列），food_co 只有 5/7 —— **k 已封顶**，无法再依据地扩。
- 数学上限（k=8、每父仅 2 子）约 81%，但本数据做不到 k=8；**当前 77.0% 就是「有真实依据」下的可达值**。为凑分给无分类列的实体硬造子类 = 编造，不做。

**EquivalentClass：不可提升（明确结论）**
- 要求：等价类只能从**词典与别名表里真实存在的同义实体**生成。
- 实测核对（`lexicon_*.json` 的 `synonym_map` / `entity_cn2en` / `field_aliases`）：两个库的任一**同义词组都不含 ≥2 个「被建模成实体」的词条**。
  `synonym_map` 覆盖的是材质/状态/类型**取值**与设备部件别名（如「闸阀: gate valve/楔式闸阀」），不是实体；`entity_cn2en` 是中文实体名→表名的一一映射，无同一表对应两个实体。
- 结论：**两库此项无可依据的等价类 → 不可提升（不猜同义、不伪造关系）。** 故 `ent_rate` 分母上的第 8 项在两库都保持空缺是**诚实的**。
