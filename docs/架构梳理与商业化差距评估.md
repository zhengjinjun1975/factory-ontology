# factory-ontology 架构梳理与商业化差距评估

> 定位：中小制造企业"数据→本体→自然语言问答"的可信 AI 底座。开源算法原子层 + 闭源编排的 Open-Core 双轨。
> 依据：README 架构声明 × 代码实测(pytest 78 passed × CI 预验证 score 99.8) × 三域深度审查(P0/P1/P2) × 竞品对标(Semantica 11.7k★/主流路线)。
> 时间：2026-09-03。注：README L372"pytest 29 项"已滞后(实际 78)，为文档待修点。

## 一、框架与架构设计梳理

### 1.1 分层架构（自下而上）
```
模型层   本地 Ollama(ornith) / 云端 DeepSeek 可切换, api_key 脱敏, 本地默认数据不出厂
  ↓
数据层   多格式 CSV/JSON/SQLite/Excel + 厂区数据库对接(db_loader) + 20+ 行业示例数据
  ↓
本体层   本体图(受控 schema) + 词典(lexicon) 全外置, 换领域只换配置
  ↓
原子层   本体认知原子(base_agent+query_agent+schema_ontology+ontology_qa_v3)
        rag 原子(knowledge/ + graph_rag + bm25 + vector)
        事件原子(event_bus)
  ↓
API层   api_server(FastAPI): 问答/溯源/扫码/统计/管理/知识库/评测/资产契约
  ↓
交付层   Web(Svelte5) + MCP server + 语音助手 + 生态插件
```

### 1.2 检索降级链（核心架构资产）
```
规则引擎(确定性零token) → 逻辑推理桥(LLM转逻辑查询确定性执行)
  → 本体引导GraphRAG(沿关系扩种子) → 向量混合检索(BM25+向量 RRF)
  → LLM兜底(咨询类, 诚实声明不编数据)
```
**价值**：不是单一检索，是一条从确定到模糊的链。规则能答的不让 LLM 答，省 token、快、可复现、零幻觉。这是区别于主流"Text-to-SQL / 向量 RAG"路线的核心差异化。

### 1.3 本体设计（轻量化本质的核心）
- **本体 = 受控 schema**，非 W3C OWL 推理体系。够用、快、能落地 > 完备。
- 属性语义角色分类（identifier/reference/measure/category/timestamp）驱动模板匹配。
- schema 显式声明 + suggest_schema 自动推断（无需手写）+ validate 约束校验 + to_nt 统一输出。
- **证据溯源**：答案带 evidence（命中实体/属性/数值），前端逐条展示"为什么是这个答案"——可解释性的实现载体。

### 1.4 Open-Core 双轨边界（商业化骨架）
| 侧 | 内容 | 策略 |
|---|---|---|
| **开源侧** | 代码 + 机制 + 方法论 + 00-03 示例词典 | Apache-2.0, 获客/信任/生态 |
| **服务侧** | 真正行业词典(随服务沉淀增长) + 编排/合规 | 保留本地, 数据不出厂红线 |

**亮点**：词典内容不进开源 = 把"行业认知资产"留在服务侧变现，同时守数据不出厂。这是可持续商业模式的地基。

## 二、系统能力盘点（实测基准）

### 2.1 能力到达率（实测 78 passed 全绿 + 三域审查）
| 能力域 | 成熟度 | 实测证据 |
|---|---|---|
| schema 驱动建模(suggest/build/to_nt) | ✅ 可用 | 内部自洽, 20+行业可建 |
| 规则问答(数量/极值/统计) | ✅ 可用 | 5领域 100% 命中 benchmark |
| 逻辑推理桥 | ✅ 可用 | logical_qa 确定性执行 |
| 本体引导 GraphRAG | ⚠️ 雏形 | 关系引导是死代码(见 §4) |
| 向量混合检索 | ✅ 可用 | RRF 融合真实现, embedding失败回落生效 |
| 证据溯源 | ✅ 可用 | 真实现(规则重扫/图带子图/doc带原文) |
| 多租户隔离 | ✅ 可用 | api_server 主链真贯穿(hash+完整性校验) |
| 生态插件框架 | ⚠️ 雏形 | 框架完整但仅 CLI 可达, 主链不调用 |
| MCP server | ✅ 可用 | 修复后溯源链完整 |
| 语音/Web/扫码溯源 | ✅ 可用 | 交付层齐备 |

### 2.2 强项（护城河候选）
1. **确定性优先 + 证据溯源**：答案可复现、零 token、可解释——正中制造企业"要的是可信不是会聊"
2. **换领域只换配置**：18+ 行业实测，规则引擎零改动
3. **数据不出厂 + 零依赖可部署**：核心纯标准库，能带进任何现场
4. **Open-Core 双轨**：词典沉淀在服务侧 = 可持续积累的认知资产

## 三、商业化差距（距"可卖"还差什么）

### 3.1 行业对标
| 对标 | 强项 | 我们差距 |
|---|---|---|
| Text-to-SQL (Spider 87%) | 通用 SQL 生成 | 我们限定模板, 开放式弱 |
| 向量 RAG 平台 | 文档问答成熟 | 我们强在结构化台账, 非文档 |
| Semantica (开源Palantir 11.7k★) | 图原生+决策溯源+高监管 | 我们轻量但缺决策哈希链/审计导出 |
| SaaS MES/BI | 报表/看板成熟 | 我们缺可视化分析层 |
| 工业知识图谱平台 | 图谱管理 | 我们是问答底座非平台 |

### 3.2 距商业化的具体差距（按阻碍程度）
**P0（信任前提，不解决卖不动）**
1. **缺"多租户运营管理面"**：现有 api_server 多租户隔离做对了，但缺企业开通/计费/配额/审计的运营层（SaaS 化必需）
2. **决策审计不可防篡改**：evidence 溯源真实现但无哈希链——企业内审/合规要"证据不可改"，Semantica 的 verify_chain 是最直接借鉴
3. **交付闭环证据**：验收有 docs 清单但缺"可自动演示的价值锚点"(停机损失/误报下降量化)

**P1（竞争力）**
4. **文档滞后**：README "29 项测试" vs 实际 78——卖点是"可信工程"，文档滞后伤可信
5. **关系引导死代码**：OG-RAG 沿关系扩种子是宣称的核心，生产从不触发
6. **无 PROV-O 审计导出**：溯源有了，导出给第三方审计员的标准格式缺

**P2（规模化）**
7. **Schema SSOT 未收敛**：三套建模引擎并存（我的审查 P0），长期维护成本/漂移风险
8. **20+ 行业数据是示例**：非真实客户沉淀，价值锚点弱
9. **Web 可视化深度**：看板/分析缺，制造企业爱看趋势图

### 3.3 商业化模式建议
- **卖结果而非卖软件**：锚定"问数据代替翻 Excel/查 SQL 的人天节省 + 决策可追责"，而非 license
- **Open-Core 落地**：开源算法(获客/信任) + 服务侧行业词典/编排/合规(订阅/项目) —— README 边界已想清，缺的是把它变成可计价产品
- **单点价值证明**：先做 1-2 个行业的"验收闭环演示"当信任敲门砖

## 四、可提升空间（结合轻量化权衡）

### 4.1 保持轻量化本质的红线
| 红线 | 原因 |
|---|---|
| 不引入完整 OWL 推理机(HermiT/Pellet) | 轻量=不依赖重量推理, 换受限schema约束子集 |
| 不引图数据库为必须 | Neo4j/Semantica式是工程重量, 我们有SQLite持久化即可 |
| 词典进服务侧不进开源 | 数据不出厂红线 + 认知资产留存 |
| 确定性优先不动摇 | 规则能答的不让LLM答, 省token快可复现 |

### 4.2 高性价比提升（不动轻量化本质）
| 优先级 | 提升 | 为什么值 |
|---|---|---|
| P0 | evidence 加**哈希链**(sequence+checksum)防篡改 | 零依赖可自实现, 服务"审核可追责"卖点, 直指企业内审 |
| P0 | **决策溯源记录**(record_decision+PROV-O导出) | 复刻 Semantica 最值钱能力, 服务高监管客户 |
| P1 | 接上**关系引导**到生产(补 ontology 入参) | 宣称的核心能力, 一行接线, 提升多跳查询 |
| P1 | **建模 SSOT 收敛**(去三套并存) | 长期维护成本, 审查已给方案 |
| P1 | schema_contract **接进发布门** | 防改类型牵一发动全身(已有工具未接线) |
| P2 | **Web 加可视化分析**(趋势/看板) | 制造企业价值感知, 仿 factory 前端模板省量 |

### 4.3 轻量 vs 商业化的平衡判断
- **不该为商业化引入的重量**：图数据库后端、完整 OWL、重型编排框架——这些是 Semantica 的路，会把"能带进任何现场"的轻量卖点毁掉。
- **该为商业化补的轻量增量**：哈希链、PROV-O、决策记录、schema_contract 接线——全是零依赖可自实现的小增量，不破坏轻量化，却把"可信/可追责"从口头变成可验证资产。
- **核心判断**：工厂本体的商业化杠杆不在"做更大更强的平台"，而在"把已极致的确定性 + 溯源，补成可被审计、可运营、可计价的可信产品"。

## 五、结论

- **架构**：分层清晰、Open-Core 双轨想清楚、检索降级链是核心差异化资产。但 Schema SSOT 未收敛是长期债。
- **系统能力**：确定性问答 + 溯源 + 多租户 + 跨行业泛化已实测可用(78 passed)，到达率高。缺口在关系引导死代码、插件主链未接、文档滞后。
- **商业化差距**：不是"技术不够"，是"可信工程未补审计闭环 + 无运营管理面 + 无价值锚点演示"。P0 = 哈希链防篡改 + 决策溯源 + 多租户运营层。
- **轻量化本质**：红线清晰。提升空间全部落在"零依赖小增量补可信/可审计"，不引入重量平台——轻量是差异化，不是障碍。

**一句话**：factory-ontology 已经是一个"确定性优先、数据不出厂、可换行业"的可信问答底座；距商业化差的是把溯源升级成可审计闭环、补上运营与价值演示——这些都能在不破坏轻量化本质的前提下用零依赖增量补齐。
