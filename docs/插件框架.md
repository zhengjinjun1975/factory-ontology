# 插件框架 — 第三方开发指南

生态插件基础框架让第三方开发者**不改主程序**，就能为系统新增能力。
核心框架（`codes/plugin_framework.py`）纯标准库、零依赖、可完全离线运行，
对齐本项目「确定性优先 · 零第三方框架」的工程纪律。

---

## 一、插件 = 一个目录

```
codes/plugins/
  <插件名>/
    manifest.json      # 插件清单（必需）
    plugin.py          # 入口模块（必需，路径由 manifest.entry 指定）
```

`<插件名>` 同时是目录名与 `manifest.name`，二者必须一致。

### manifest.json

```json
{
  "name": "example_decision",   // 唯一插件名，必须与目录名一致
  "kind": "decision",           // 主类型：decision / data_source / push / template
  "version": "1.0.0",           // 版本号
  "entry": "plugin.py",         // 入口文件名（相对插件目录）
  "description": "一句话说明",   // 可选
  "author": "…",                // 可选
  "provides": ["maintenance_priority"]  // 提供的扩展点 id（可选）
}
```

必需字段缺失、`kind` 非法、`name` 与目录名不符、入口文件不存在，
都会在扫描时被逐个容错报告（不中断其他插件的加载）。

## 二、入口模块与生命周期

入口模块定义一个 `Plugin` 类（继承 `BasePlugin` 或实现相同接口），
按 **load → register → run → unload** 四阶段被框架调度：

```python
from plugin_framework import BasePlugin

class Plugin(BasePlugin):
    name = "example_decision"
    kind = "decision"
    version = "1.0.0"

    def load(self, ctx):      # [可选] 初始化。ctx 提供 plugins_dir/registry/plugin_dir 等
        pass

    def register(self, reg):  # [可选] 把本插件能力登记进扩展点注册表
        reg.register("decision", "maintenance_priority", self._handler,
                     plugin=self.name, meta={"description": "…"})

    def run(self, params):    # [必须] 执行插件主逻辑，返回可 JSON 序列化结果
        return {"ok": True}

    def unload(self, ctx):    # [可选] 释放资源
        pass
```

### 各阶段职责

| 阶段 | 时机 | 说明 |
|------|------|------|
| `load(ctx)` | 插件被加载时 | 初始化资源；ctx 携带 plugins_dir/registry/plugin_dir/manifest/module |
| `register(reg)` | load 之后 | 通过 `reg.register(kind, id, handler)` 对外暴露能力 |
| `run(params)` | 用户调用 `plugin run <名>` | 插件主逻辑入口 |
| `unload(ctx)` | 插件被移除/卸载时 | 释放资源；框架自动注销该插件登记的全部扩展点 |

## 三、扩展点类型

扩展点注册表（`ExtensionRegistry`）按 `(kind, id)` 统一管理四类能力：

| kind | 用途 | handler 语义 |
|------|------|--------------|
| `decision`   | 决策规则 | 输入事实/参数 → 输出决策结论（本示例插件即此类） |
| `data_source`| 数据源     | 按查询参数 → 输出结构化数据行 |
| `push`       | 推送通道   | 把消息推送到外部系统（钉钉/微信/Webhook 等） |
| `template`   | 模板渲染   | 按变量 → 渲染文本 |

**handler 统一签名**：`fn(params: dict) -> 任意可 JSON 序列化结果`。

调用方式（系统核心或另一插件皆可）：

```python
reg.call("decision", "maintenance_priority", {"records": [...]})
```

同一 `(kind, id)` 重复注册会抛冲突异常；卸载插件时框架自动注销其扩展点。

## 四、CLI 用法

```bash
cd codes

# 列出插件（可加类型过滤）
python run.py plugin list
python run.py plugin list decision

# 加载并运行插件主逻辑
python run.py plugin run example_decision '{"records":[{"device_id":"D001","air_temperature":302}]}'

# 调用已登记的扩展点
python run.py plugin ext decision maintenance_priority '{"records":[...]}'
python run.py plugin ext decision failure_alert '{"records":[...]}'

# 安装插件（本地目录 / zip / tar.gz 归档，可指定别名、覆盖）
python run.py plugin install /path/to/my_plugin
python run.py plugin install /path/to/my_plugin.zip --name 别名
python run.py plugin install /path/to/my_plugin --force

# 移除插件
python run.py plugin remove my_plugin
```

安装后会立即加载验证；`--force` 覆盖同名已存在的插件。

## 五、写一个插件（最小步骤）

1. 建目录 `codes/plugins/<你的插件名>/`
2. 写 `manifest.json`（name/kind/version/entry 四要素）
3. 写入口文件，定义 `Plugin` 类并实现 `run()`；需要对外暴露能力就在 `register()` 里登记扩展点
4. `python run.py plugin list` 确认被发现，`python run.py plugin run <名> '{}'` 运行
5. （可选）打包成 zip 或用目录方式分发给别人 `plugin install`

参考实现：`codes/plugins/example_decision/`，可直接独立运行 `python plugin.py` 自测。

## 六、设计原则与边界

- **零依赖**：框架只用 Python 标准库，第三方插件也应尽量少引第三方包，保证可离线。
- **确定性优先**：本示例是纯规则决策，零 LLM，输出可复现、带判断依据。
- **容错**：扫描/加载单个插件失败不影响其余插件；错误在 `list` 时以 ⚠️ 提示。
- **安全**：插件即代码，安装运行第三方插件前请自行审查其入口源码。
