# 需求：错误分类加固 + 边界安全（区分模型/数据/网络错误）

> 用户反馈：前端显示"网络错误"，但不知道具体是模型配置问题还是数据没连上。
> 目标：错误提示明确分类，区分网络错误/模型配置错误/数据错误/词典错误；边界安全。

## 现状（问题）
前端 App.svelte 的 catch 分支统一显示"网络错误，请确认服务已启动"（约 105/142 行）——不区分：
1. 网络错误（fetch 抛异常 = 服务没启动/断网）
2. 模型配置错误（LLM 调用失败：key 未配置/模型不可用）
3. 数据错误（建模失败/词典不可用/数据读取失败）
4. 后端业务错误（res.error 已含具体信息但前端可能覆盖）

## 目标文件
- `E:\open-source\factory-ontology-kit\web\src\App.svelte`（前端错误处理）

## 要求
1. **区分错误类型**，前端明确显示：
   - **网络错误**（fetch 抛异常）："网络错误：服务未启动或连接失败，请确认后端已运行"
   - **后端业务错误**（res.error 存在）：直接显示 res.error（保留后端具体信息，如"模型 key 未配置"、"词典不可用请重新建模"、"读取失败"）
   - **模型配置错误**：若 res.error 含"key"/"api_key"/"模型"/"Ollama"/"未配置" → 提示"模型配置问题，请在模型管理中检查"
2. **错误不覆盖**：优先显示后端返回的 res.error（具体），仅 fetch 抛异常才显示"网络错误"
3. 边界安全：错误消息转义防 XSS（不用 innerHTML 插错误文本）

## 约束
- Svelte 5（$state/$props）
- 极简：改 doDefaultExample/doLocalModel/doAsk 等 catch 分支的错误显示
- 保留后端 res.error 的具体信息

## 验收
1. 后端返回 res.error 时前端显示该错误（不覆盖为"网络错误"）
2. 模型配置错误明确提示"模型配置问题"
3. fetch 抛异常才显示"网络错误：服务未启动"
4. vite build 无 error
5. pytest 29 passed
