# 需求：数据源输入改为单一统一选择器（对齐 solo-agent-kit，去冗余）

> 用户反馈：数据输入有"用默认示例建模 + 浏览数据文件 + 点击选择文件"三个并列端口，能力冗余、界面丑。
> solo-agent-kit 的正确做法：**一个统一的数据源选择器**（openDsModal 弹窗），点开显示文件浏览器（默认示例目录 + 盘符/上级导航），Ctrl/Shift 多选，确认。单一入口，干净。

## 参考（solo-agent-kit web/app.js 557-614）
- `openDsModal()`：点"选择数据文件"→ 弹出选择器 → `browseDir('')` 默认示例目录 → 渲染文件列表（盘符/上级/子目录/文件）
- `dsSelectFile(path, evt)`：Ctrl/Shift 多选，高亮已选，`dsMulti` 数组
- `dsConfirm()`：确认选中文件
- 单一入口：各模块一个"选择数据文件"卡片，共用同一个选择器

## 现状（factory-ontology，问题）
数据建模 tab 数据源输入区有**三个并列端口**：
1. 用默认示例建模（按钮）
2. 浏览数据文件（点击弹出选择器）
3. 点击选择文件（系统 `<input type="file">`）
→ 能力冗余、界面丑。

## 目标文件
- `E:\open-source\factory-ontology-kit\web\src\App.svelte`（数据建模 tab 数据源输入区）

## 要求（对齐 solo-agent-kit 单一选择器）
1. **统一为单一"选择数据文件"入口**：数据源输入区只保留一个「📂 选择数据文件」按钮/卡片
2. **点击 → 弹出文件选择器**（browseOpen 状态，类似 solo 的 modal）：默认调 browseFiles('data_valve') 显示 data_valve 示例目录，渲染文件列表（📄 文件名 + 路径）+ 目录导航（盘符/上级/子目录）
3. **多选**：Ctrl/Shift 点击多选文件，高亮已选，显示"已选 N 个文件"
4. **确认建模**：「确认并建模（N 个文件）」→ 逐文件 readDataFile → setupOntologyMulti
5. **去掉冗余端口**：
   - 移除"用默认示例建模"按钮（因为选择器默认就在 data_valve，用户直接选即可；或保留为次级"用默认示例一键"但非并列主端口）
   - 移除"点击选择文件"系统 `<input type="file">`（统一用弹出的文件选择器）
6. 保留：数据库接入（本地厂区局域网，独立折叠区）
7. **示例数据不摊开**：一进页面不显示文件列表，点「选择数据文件」才弹出

## 约束

- 不破坏：数据库接入/问答/看板
