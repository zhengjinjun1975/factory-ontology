# factory-ontology 深度梳理与漏洞审查报告

> 审查方式：三子任务并行深读（建模域 / 检索链路 / 架构多租户域），全部只读 + 程序化 AST 签名提取 + 关键方法体精读。行号已逐一核对。
> 审查基准：`codes/` 约 40 个 .py / 1.4 万行；测试基线 75 passed / 3 failed（2 个 test_api 缺 fastapi 依赖非逻辑 bug，1 个 test_mcp_reverse_trace 已归因）。
> 对照：Semantica（开源 Palantir，11.7k star）同域借鉴点已标注。

## 一、整体架构梳理

工厂本体域按"建模引擎 → 词典层 → 问答/校验/API"分层，核心矛盾是**建模 SSOT 未收敛**。

```
原始数据(CSV/SQLite/Excel)
  → 建模层: 【三套并存引擎】schema_ontology(to_nt) / csv_to_owl / multi_table
  → 词典层: lexicon.py(收敛好) + industrial_dict_loader + absorb_public_dict(滚雪球)
  → 问答:   ontology_qa_v3(规则) → logical_qa(桥) → graph_rag(图) → bm25+vector(RRF)
  → 校验:   ontology_check(真健康门) / schema_contract(孤儿)
  → 入口:   api_server(生产主线) / agents(原子) / mcp_server / run.py(CLI)
```

### 检索降级链（生产主线 api_server._ask_impl 647-849）
规则 → 跨域拦截 → 逻辑桥 → 本体引导 GraphRAG → 咨询拦截 → 混合检索(RRF) → docRAG → LLM 兜底。

**但降级链分散成三套并行实现，行为不一致**：

| 入口 | 载体 | 覆盖环节 | 缺口 |
|---|---|---|---|
| 生产主线 | api_server | 全链 | 无（最完整） |
| 原子Agent | agents/query_agent | 规则→图→混合→兜底 | **缺逻辑桥一环** |
| MCP | mcp_server | 规则→逻辑桥→图→BM25(仅稀疏) | **无向量/RRF，权重另起炉灶** |

## 三、对照 Semantica 的可修借鉴点

（Semantica 源码实证：溯源哈希链 verify_chain / record_decision / PROV-O 审计导出）

| Semantica 能力 | 我们现状 | 借鉴落地 |
|---|---|---|
| **溯源哈希链** verify_chain（sequence_id+checksum+prev_checksum 三校验防删行） | 规则答案带 evidence 溯源，但无篡改检测 | **高价值 P0 级**：给 evidence/溯源加哈希链，防"答案可信但被改"，服务审核可追责 |
| **决策一等公民** record_decision（决策节点+实体链接+reasoning_embedding） | 插件有 decision 扩展点，但主链路不调用 | 若插件决策真需要，接入决策记录 |
| **PROV-O 审计导出** | evidence 有但无 PROV-O 导出 | P2：加 W3C PROV-O/CSV 审计导出 |
| **完整性校验防脏本体** _has_required_relations | api_server 有，mcp 无 | **P1-1 直接修**：mcp 复用 |
