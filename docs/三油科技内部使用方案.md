# 三油科技内部使用方案 — 用 factory-ontology 做企业知识管理

> 目标：不依赖外部数据/客户，先用框架管三油科技自己的业务数据，把交叉佐证做实锤，同时沉淀一套可复用的内部工具。

## 一、三个内部知识库场景

### KB-A：设备/阀门台账（最贴合主营业务）
**数据**：客户阀门/设备台账（型号/口径/压力等级/材质/安装日期/保修期/维修记录/状态/客户）
**价值**：
- 问答："X 客户有哪些设备"、"保修期内的设备"、"维修次数最多的型号"、"压力等级≥4MPa 的设备"
- **溯源**：设备→批次→零部件（哪批件出了问题，影响哪些客户设备）——**与食品安全同理，是质量追溯核心**
- **预警**：保修期快到期设备、超期未检设备

**表结构**（对齐框架 schema）：
`sanyou_equipment.csv`（id/设备名/型号/口径/压力等级/材质/客户/安装日期/保修期/状态）
`sanyou_batches.csv`（生产/供货批次）+ `sanyou_batch_part.csv`（批次-部件关联）

### KB-B：合同台账
**数据**：销售/采购合同（合同号/客户/供应商/金额/签订日/交付期/回款/状态）
**价值**：
- 问答："Q3 到期合同"、"金额>50 万的合同"、"未回款合同"、"给 X 客户签过哪些合同"
- 财务/履约提醒（回款逾期、交付临期）

**表结构**：`sanyou_contracts.csv`（id/合同号/客户/供应商/金额/签订日/交付期/回款状态/负责人）

### KB-C：技术文档（文档问答）
**数据**：技术标准、阀门选型手册、维修手册、质检报告（文档类）
**价值**：文档问答（"安全阀选型标准"、"闸阀维修步骤"）+ 图谱关联（文档↔设备型号↔标准）

## 二、落地步骤（每 KB 约 1-2 天）

```
1. 建库骨架   python new_kb.py sanyou_a --name "设备台账" --icon "🔧"
2. 接入数据   把设备/合同 CSV 放进 data_sanyou_a/（或 ERP 直连 db_loader）
3. 配词典     编辑 config/lexicon_sanyou_a.json（设备/合同的字段中英映射）
4. 部署       设 FOOD_KB=sanyou_a 启动 python api_server.py
5. 使用       📱 手机问设备/合同 · ⚙️ 管理后台 · 📄 导出台账/预警
6. 验证       python data_quality.py + benchmark
```

## 三、价值与 ROI

| 场景 | 直接价值 |
|------|----------|
| 设备台账 | 库存/维护/保修查询从翻表格 → 一句话问答；质量追溯秒级定位 |
| 合同台账 | 履约/回款提醒、客户合同全景，减少漏单/逾期 |
| 技术文档 | 选型/维修/质检资料即问即答，新人上手快 |

**间接价值**：内部用起来 = 交叉佐证实锤（"三油科技真实采用"），开源项目从"个人方法论"变"被企业采用"。

## 四、分工

- **我（Hermes）**：框架已就绪；可代建示例 KB、写词典模板、做 QA 验证、设计表结构
- **三油科技**：提供脱敏设备/合同数据、确认字段语义、内部部署、日常使用
- **CodeAgent**：每次改动做代码审查 + 端到端测试

## 五、优先级建议

**先做 KB-A（设备台账）**——最贴合主营业务、最能体现溯源价值、最容易拿到数据（内部设备记录）。
KB-B（合同）次之（财务敏感，需确认脱敏）。KB-C（文档）最后（文档问答依赖模型，先验证效果）。

## 六、诚实边界

- 需三油科技真实（脱敏）数据才能从"示例"变"实锤"——数据是唯一前提
- 内部先用起来是"采用"的起点，不等于对外产品化
